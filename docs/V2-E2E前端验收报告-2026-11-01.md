## 3. 缺陷清单

### P0-1 审核被驳回后前端无法「重新提交」（阻断）

* **位置**：`angular/src/app/admin/libraries/audits/review-center.component.html:204`
  ```html
  @if (!dto.canDecide && dto.statusName === '已驳回' && dto.canWithdraw) {
    <button nz-button (click)="resubmit()">重新提交</button>
  }
  ```
* **根因**：后端 `ReviewTicketAppService` 中 `CanWithdraw = ticket.Status == Pending`，而「已驳回」时 `Status=Rejected`，故 `canWithdraw` 恒为 `false` —— 该条件永远不成立，按钮永不渲染。
* **影响**：驳回后用户只能再次「编辑」生成新审核单，**轮次不递增**（实测新单 `roundNo=1`，而 `POST /review-ticket/{id}/resubmit` 接口本身是正确的 `roundNo=2`），审核历史割裂、与手册 M1-6 期望不符。
* **建议**：后端 DTO 增加 `CanResubmit`（提交人 && 状态为 Rejected），前端改用该字段。

### P0-2 协作校教师在「我的共建任务」没有「提交」按钮，无法提交交付物（阻断）

* **位置**：`src/KnowledgeHub.Application/ResourceLibraries/BuildTaskAppService.cs`
  * `GetTasksAsync`：`var query = await _taskRepository.WithDetailsAsync(x => x.Items);` —— **未加载 `Collaborators`**
  * `ToTaskDtoAsync`：`CanSubmit = ... && (tenantId.HasValue && task.Collaborators.Any(x => x.SchoolId == tenantId.Value))` —— 集合为空 → 恒 `false`
* **影响**：V2 共建任务主线在**前端完全不可用**（协作校拿不到提交入口）；主责校同样受影响（`OwnerUserId` 为空）。API 直调 `submit-delivery` 正常，说明是纯后端 DTO 装配缺陷。
* **建议**：`WithDetailsAsync(x => x.Items, x => x.Collaborators)`（`GetTaskWithDetailsAsync` 已正确加载，仅列表路径漏了）。

### P0-3 企业账号看不到任何资源库，无法向前端贡献内容（阻断）

* **位置**：`src/KnowledgeHub.Application/ResourceLibraries/ResourceLibraryAccessService.CanViewCoreAsync`
  * 可见性判定只覆盖「被分配教师 / 主建专业默认教师 / 院校管理员」，**没有 EnterpriseUser 分支**。
* **影响**：文档「4.7 企业用户页面地图」声称企业可「向本校主建库贡献内容」，实际 `my-libraries` 返回 `[]`，教学资源库工作台显示「你可见的 0 个教学资源库」。企业只能在 API 层贡献（认证后 `attach=200`）。
* **建议**：为 `EnterpriseUser` 增加「本租户主建库可贡献/可浏览」的可见性分支，或在 `GetVisibleLibrariesAsync` 对企业角色放宽 `canContribute` 判定。

### P1-4 企业工作台没有「编辑企业资料」入口 → 新开通企业永远无法认证

* **位置**：`angular/src/app/enterprise/workbench/enterprise-workbench.component.ts:67` 定义了 `readonly editOpen = signal(false);`，模板中**从未使用**。
* **复现**：学校「开通企业账号」→ 企业登录 → 企业工作台显示「统一社会信用代码：未填写」→ 点「提交企业认证」→ 提示「**请先完善企业资料**」，无处可改。
* **影响**：通过 UI 新建的企业是死路（只有演示企业 `ent-demo` 因库中预置了完整资料才能认证）。
* **建议**：企业工作台补「编辑资料」弹窗（后端 `PUT /api/app/enterprise/{id}` 已可用）。

### P1-5 企业侧没有「接受/拒绝学校响应」入口 → 产教合作闭环断裂

* **证据**：企业工作台「合作需求」列表行仅有「关闭」操作；前端没有任何组件调用 `decide-response` / `responses/{demandId}`（代理已生成但未使用）。
* **影响**：学校响应后，企业无法在 UI 接受 → 无法建项目 → 产教闭环停在「校方已响应」。
* **建议**：企业工作台需求行增加「查看响应 / 接受 / 拒绝」，接受后可直接「建项目」。

### P1-6 学生端课程详情页不展示跨校引用内容

* **证据**：`/student/courses/{id}` 「课程资源 0」；全仓前端无组件引用 `course-shared-ref` / `check-access`。
* **影响**：引用即使生效，学生端也没有入口；「撤销后显示『资源暂不可用』」无处落地（P4 遗留 D3）。
* **建议**：学生课程详情的「课程资源」页签合并「课程自带资源 + 本课生效的跨校引用」，不可用时渲染占位。

### P1-7 共享候选列表包含他校资源，提交后报「资源不存在。」

* **复现**：教学资源库工作台 → 共享资源 → 候选列表首行是 guozhou 租户的「国州-共建课件.pptx」→ 勾选共享 → `POST /api/app/teaching-resource-library/{id}/attach` → **403「资源不存在。」**
* **原因**：候选来自「资源列表」接口（含共享给他校/他校共享给我的资源），未按租户过滤。
* **建议**：候选列表过滤为「本校租户资源」；或 attach 失败时提示「该资源属于其他学校，无法共享到本校库」。

### P2-8 库内容「待审可见性」按资源创建人判定，提交人看不到自己提交的内容

* **位置**：`TeachingResourceLibraryAppService.FilterByPublication` 的 `creatorSelector` 取的是 `Resource.CreatorId`，而非 `ResourcePublication.CreatorId`。
* **证据**：`dfa` 由 wwq 提交入库，但资源创建人是 qidi-admin → wwq 在「库内容」看不到；自己创建的 `1234` 能看到。
* **建议**：改用发布记录的提交人判定「提交人/审核人可见待审项」。

### P2-9 资源库「内容」计数与实际库内容不一致

* **证据**：`国州·多校共建测试库` DTO `resourceCount=0 / courseCount=2`，实际 `contents` 共 5 条（2 资源 + 2 课程 + 1 审核中）。
* **原因**：统计口径基于 `Resource.LibraryId` 旧字段，未纳入「准入发布」记录。
* **建议**：统计与 `GetContentsAsync` 口径对齐（并集 + 已发布/待审分列）。

### P2-10 驳回后「再次编辑」不累加轮次

* 与 P0-1 同源：`重新编辑` 生成全新审核单 `roundNo=1`，无法体现「第 2 轮」。若走 `resubmit` 接口则正确为 2。

### P2-11 审核详情弹窗在「通过/驳回」后不自动关闭

* 现象：点「通过」后弹窗仍停留并显示「已通过」，需手动关闭；列表会短暂同时出现空状态「当前没有待你审核的内容。」与新数据。
* 建议：通过/驳回成功后自动 `closeDetail()`；空状态与表格用同一 loading 条件互斥。

### 观察项（非缺陷）

* 资源库列表**没有**「提交审核」按钮：新建库即自动进入审核流（与手册 U1 描述有出入，但流程更顺）。
* 交付记录里「内容」列显示的是资源 GUID（`3a23be7c-…`）而不是资源名，建议补名称回显。
* `docs/V2-测试账号与环境.md` 中的 `guozhou/qa_gz_stu` 账号在本地库中不存在，建议更新。

## 3.3 部署侧：pgvector 落地

| 项 | 结果 |
|---|---|
| 现状核查 | iketong 与生产（119.45.170.4）均为 `postgres:16-alpine`，**无 pgvector**；迁移 `AddPgvectorKnowledgePointEmbeddings` 早已执行但扩展安装失败被静默跳过 → 只有 `Embedding real[]`，无 `EmbeddingVector`/HNSW |
| 影响 | 知识点语义检索回退为进程内余弦（功能可用，但大数据量下性能与召回下降） |
| 方案 | 自建镜像 `Dockerfile.postgres-pgvector`（官方 alpine + 编译 pgvector 0.8.0），**同源 alpine 避免 musl/glibc 的 collation 风险**；compose 改用 `${POSTGRES_IMAGE}`；两个 deploy 脚本新增 `postgres-pgvector` 子命令 |
| 补列 | 新迁移 `EnsurePgvectorEmbeddingColumn`（幂等）：`CREATE EXTENSION vector` → `AppKnowledgePoints.EmbeddingVector vector(1024)` → 从 `real[]` 回填 → HNSW 余弦索引 |
| iketong 实测 | 镜像已切换、`vector 0.8.0` 已安装、站点 200；`./deploy-iketong.sh migrator` 后补建列与索引 |
| 生产（119.45.170.4） | compose/.env 同步已改，执行 `./deploy-to-remote.sh postgres-pgvector` + `migrator` 即可（生产库建议先在低峰期、确认有备份后执行） |
