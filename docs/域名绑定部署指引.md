# 域名绑定部署指引（学校专属域名）

> 对应能力：每所学校有自己的域名或子域名；通过该域名访问时，系统自动落入该校租户，
> 只显示本校内容，登录账号也必须是本校账号。
> 平台域名（`iketong.com` / `www.iketong.com`）行为**完全不变**。
>
> 设计说明见 `docs/域名绑定多租户方案.md`；本文只讲**怎么把域名接进来**。

---

## 一、整体链路

```
浏览器  https://qidi.school.iketong.com/
   │  (宝塔终结 HTTPS，透传 Host + X-Forwarded-Proto)
   ▼
宝塔 Nginx  ──►  容器 Nginx (127.0.0.1:4200, server_name _)
                          │  静态资源（SPA）
                          │  /api /connect /.well-known ──► API 容器 (44354)
                          ▼
                    API：Host 头 → 学校域名解析器 → 租户上下文
```

**容器内 Nginx 无需为学校域名改动任何东西** —— 它本来就是 `server_name _` 兜底，
且所有反代 location 都带 `proxy_set_header Host $host`，域名信息本来就传到了 API。

---

## 二、配置步骤

### 步骤 1：平台侧填基础域名（若用子域名方式）

设置项：`KnowledgeHub.Domain.BaseDomains`，逗号分隔，例如：

```
school.iketong.com
```

- 留空 = 只支持「学校自有独立域名」（`School.Domain`），不启用子域名推断。
- 存储位置：全局设置（ProviderName = `G`），host 超管在管理端维护。
- 基础域名**不要**包含平台域名本身（`iketong.com` / `www.iketong.com`），
  否则平台域名会被当成某个学校的子域名前缀。

### 步骤 2：给学校配域名

管理端 → **学校设置**（`/admin/school`）→ 「域名绑定」区：

| 字段 | 用途 | 示例 |
|---|---|---|
| 学校自有域名 | 完整主机名，独立域名场景 | `qidi-edu.cn` |
| 子域名前缀 | `{前缀}.{基础域名}` 场景 | `qidi` → `qidi.school.iketong.com` |

两种都可以只填一种。两者都有唯一索引，冲突时保存会明确报错。

> 域名变更后解析缓存（10 分钟）会被主动失效，旧域名立即失效。

### 步骤 3：DNS 解析

把学校域名解析到平台服务器 IP：

```
qidi.school.iketong.com.  IN A  <平台服务器IP>
```

### 步骤 4：宝塔加站点 / 加域名

1. 宝塔面板 → 网站 → 找到 `iketong.com` 站点 → **域名管理** → 添加 `qidi.school.iketong.com`。
   （或为独立域名新建站点，反向代理到 `http://127.0.0.1:4200`。）
2. **反向代理头必须透传**（宝塔默认已带，确认即可）：
   ```nginx
   proxy_set_header Host $host;
   proxy_set_header X-Forwarded-Proto $scheme;   # 关键：$scheme 在宝塔层是 https
   proxy_set_header X-Real-IP $remote_addr;
   proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
   ```
   `X-Forwarded-Proto` 必须是 **https**（宝塔终结 TLS 后 `$scheme` 即 https）。
3. **申请 SSL 证书**给该域名（宝塔 → SSL → Let's Encrypt），并开启强制 HTTPS。

> 容器内 Nginx（`etc/docker/nginx-proxy-iketong.conf`）已把
> `X-Forwarded-Proto` 固定为 `https`（`$scheme_default`），与宝塔层一致，无需改动。

## 三、必须确认的两件事

### ① 协议透传（决定令牌能否签发/校验）

OpenIddict 的 issuer 现在**按请求动态推导**（`AuthServer:StaticIssuer` 默认 false），
每个域名签发自己域名的令牌，SPA（origin = 当前域名）才能通过 discovery 校验。

推导结果 = 请求的 **协议 + 主机名**，所以：

- 宝塔 → 容器 Nginx → API 这条链上，`X-Forwarded-Proto` 必须一路传到 API；
- 容器 Nginx 已固定为 `https`（iketong 配置）✅；
- 宝塔层若改成 `http` 或删掉该头，issuer 会变成 `http://...`，与浏览器 `https://` 不符 →
  **登录后立刻掉线（401）**。

**排障**：打开 `https://<学校域名>/.well-known/openid-configuration`，看 `issuer` 字段。
必须是 `https://<学校域名>/`，若是 `http://` 就是协议没透传对。

### ② 静态 issuer 回退开关

若某个老部署无法满足上面的协议透传条件，可临时写死 issuer：

```bash
# docker-compose 环境变量
AuthServer__StaticIssuer=true
```

此时恢复成「所有域名共用平台 issuer」的老行为（学校域名的登录会因 discovery 不匹配而不可用，
但平台域名不受影响）。**仅作回滚手段**，新增学校域名时应保持默认的动态 issuer。

## 四、本地开发

### hosts

无需改 `/etc/hosts` —— macOS / Linux 浏览器会把 `*.localhost` 直接解析到回环。

```bash
# 直接访问
http://qidi.localhost:4200/
```

如需其它域名，在 `/etc/hosts` 加一行即可：

```
127.0.0.1 qidi.school.localhost
```

### 平台基础域名（本地）

设置项 `KnowledgeHub.Domain.BaseDomains` 填 `localhost`，
学校配 `Slug = qidi`，即可用 `http://qidi.localhost:4200/` 访问。

### dev server 代理

`angular/proxy.conf.js` 已统一：

- `changeOrigin: false` —— 保留浏览器原始 Host，域名才能传到后端；
- `X-Forwarded-Proto: http` —— 让 `/api` 与 `/connect` 推导出的 issuer 一致
  （否则登录后立刻 401 掉线）。

> 改完 `proxy.conf.js` 需要重启 dev server（`./dev.sh restart angular`）。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 学校域名下首页仍显示所有学校 | 后端未重启 / 迁移未应用 | 重新应用迁移 `20261024031912_AddSchoolDomainBinding` 并重启 API |
| 学校域名下 `isSchoolDomain=false` | 学校没配域名，或基础域名不含该后缀 | 检查 `/admin/school` 的域名配置与 `BaseDomains` |
| 刚配好域名仍不生效（最多 10 分钟） | 该主机名此前被缓存为「未命中」 | 保存学校档案时会主动失效新域名对应缓存；若手工改库则等 TTL 或重启 API |
| 登录后立刻掉线 / 401 | 协议透传不对，issuer 不一致 | 看 discovery 的 `issuer`，核对宝塔与容器 nginx 的 `X-Forwarded-Proto` |
| 在 A 校域名登录后切到 B 校域名被踢回登录页 | **符合设计**：令牌按域名签发，跨域必须重新登录 | 预期行为，非缺陷 |
| 页面一直停在启动闪屏 | 前端资源 404 | 检查宝塔反代到 4200 的路径是否正确（`/` 走静态，`/api` 走 API） |
| 学校域名下打开管理端 401 | 令牌所属租户与域名不一致 | 预期行为，请用本校账号在本校域名登录 |
| 改了域名后旧域名仍生效 | 解析缓存 | 正常最长 10 分钟；保存时会主动失效对应 key |
