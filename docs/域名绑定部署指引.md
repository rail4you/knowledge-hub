# 域名绑定部署指引（学校专属域名）

> 对应能力：每所学校有自己的域名或子域名；通过该域名访问时，系统自动落入该校租户，
> 只显示本校内容，登录账号也必须是本校账号。
> 平台域名（`iketong.com` / `www.iketong.com`）行为**完全不变**。
>
> 设计说明见 `docs/域名绑定多租户方案.md`；本文只讲**怎么把域名接进来**。

---

## 一、整体链路

```
浏览器  https://qidi.iketong.com/
   │  (宝塔终结 HTTPS，透传 Host + X-Forwarded-Proto)
   ▼
宝塔 Nginx  ──►  容器 Nginx (127.0.0.1:4200, server_name _)
                          │  静态资源（SPA）
                          │  /api /connect /.well-known ──► API 容器 (44354)
                          ▼
                    API：Host 头 → 学校域名解析器 → 租户上下文
```

**容器内 Nginx 无需为学校域名改动任何东西** —— 它本来就是 `server_name _` 兜底，
且所有反代 location 都带 `proxy_set_header Host $host`，域名信息本来就传到了 API。
学校域名只是**加进宝塔站点的 `server_name` 与证书 SAN**（`bt-school-domain` 命令一键完成）。

### 两种接入方式

| 方式 | 学校侧配置 | 访问地址 | 运维要点 |
|---|---|---|---|
| **A. iketong 子域名**（推荐先落地） | 只填「子域名前缀」 | `qidi.iketong.com` | 平台统一签证书；`bt-school-domain` 一键接入 |
| **B. 学校独立域名** | 填「学校自有域名」 | `qidi-edu.cn` | 学校自己解析 DNS/申请证书，或交给运维挂载 |

两种可并存：同一所学校配了 A 和 B，访问哪个域名都进同一所学校。

## 二、配置步骤

> **两种接入方式，生产都支持：**
>
> | 方式 | 学校侧配置 | 访问地址 | 适合 |
> |---|---|---|---|
> | **A. iketong 子域名** | 只填「子域名前缀」 | `qidi.iketong.com` | 平台统一签发证书、统一运维（**推荐先落地这个**） |
> | **B. 学校独立域名** | 填「学校自有域名」 | `qidi-edu.cn` | 学校已有自己的域名与证书 |
>
> 两种方式可并存：学校同时配 A 和 B，访问哪个域名都进同一所学校。

### 方式 A：iketong 子域名（以启迪学院 qidi 为例）

**第 1 步：DNS 解析**

在域名服务商处加一条 A 记录，指向平台服务器 IP（iketong 现网为 `47.99.245.49`）：

```
qidi.iketong.com.   IN A   47.99.245.49
```

> DNS 生效后才能申请证书，否则 Let's Encrypt 校验会失败。

**第 2 步：接入宝塔站点与证书（一条命令）**

在部署机上执行：

```bash
cd etc/docker
./deploy-iketong.sh bt-school-domain qidi.iketong.com
```

这条命令会做四件事：

1. 把域名追加进 `.env.iketong` 的 `SCHOOL_DOMAINS`（逗号分隔，追加去重）；
2. 同步 `.env` 到远端服务器；
3. 重跑宝塔站点配置 —— `server_name` 变成
   `iketong.com www.iketong.com qidi.iketong.com`；
4. 重签 Let's Encrypt 证书，SAN 变为 `iketong.com + www.iketong.com + qidi.iketong.com`。

> 宝塔站点是同一套容器反代，**不用新建站点**，域名挂在现有站点上即可。
> 容器内 Nginx 无需任何改动。

**第 3 步：管理端配置基础域名与学校前缀**

| 位置 | 配置项 | 值 |
|---|---|---|
| 管理端 → 学校设置 → **平台设置 · 域名绑定** | 平台基础域名 | `iketong.com` |
| 管理端 → 学校设置 → 启迪学院的 **域名绑定** 区 | 子域名前缀 | `qidi` |

保存后立即生效（保存时会主动失效域名解析缓存）。

**第 4 步：验证**

```bash
# 应返回 isSchoolDomain=true, schoolName=启迪学院
curl -sk -H "Host: qidi.iketong.com" https://localhost:44305/api/public/current-tenant

# 平台域名必须不受影响
curl -sk -H "Host: www.iketong.com" https://localhost:44305/api/public/current-tenant
```

浏览器访问 `https://qidi.iketong.com`：首页只显示启迪学院、登录页机构锁定、
用别校账号登录会提示「该账号不属于该学校」。

### 方式 B：学校独立域名

1. 学校自己把域名解析到平台服务器 IP；
2. 学校自行申请证书，或把证书交给运维装到宝塔；
3. 管理端 → 学校设置 → 填「学校自有域名」（如 `qidi-edu.cn`）；
4. 运维在宝塔把该域名加进站点 `server_name` 并签发/挂载证书
   （`./deploy-iketong.sh bt-school-domain qidi-edu.cn` 同样适用）。

> 独立域名方式不依赖 `BaseDomains`，适合「学校已有域名」的场景。

### 步骤 1（两种方式通用）：平台基础域名（若用子域名方式）

管理端 → **学校设置** → **平台设置 · 域名绑定** → 基础域名填：

```
iketong.com
```

- 留空 = 只支持「学校自有独立域名」（方式 B），不启用子域名推断。
- 存储位置：全局设置 `KnowledgeHub.Domain.BaseDomains`（ProviderName `G`），host 超管在管理端维护。
- 基础域名**不要**填平台自身域名 `iketong.com` / `www.iketong.com`
  —— 管理端会直接拒绝（否则平台入口会被当成某校的子域名前缀）。
- 平台的 `www.iketong.com` 另有两重保护：解析器对平台主机名直接放行不解析为学校；
  且子域名前缀 `www` 属保留字，学校无法占用。

## 三、必须确认的两件事

### ① 协议透传（决定令牌能否签发/校验）

OpenIddict 的 issuer 现在**按请求动态推导**（`AuthServer:StaticIssuer` 默认 false），
每个域名签发自己域名的令牌，SPA（origin = 当前域名）才能通过 discovery 校验。

推导结果 = 请求的 **协议 + 主机名**，所以：

- 宝塔 → 容器 Nginx → API 这条链上，`X-Forwarded-Proto` 必须一路传到 API；
- 容器 Nginx 已固定为 `https`（iketong 配置）✅；
- 宝塔层若改成 `http` 或删掉该头，issuer 会变成 `http://...`，与浏览器 `https://` 不符 →
  **登录后立刻掉线（401）**。

**排障**：打开 `https://<学校域名>/.well-known/openid-configuration`，看 `issuer` 字段。
必须是 `https://<学校域名>/`，若是 `http://` 就是协议没透传对。

### ② 静态 issuer 回退开关

若某个老部署无法满足上面的协议透传条件，可临时写死 issuer：

```bash
# docker-compose 环境变量
AuthServer__StaticIssuer=true
```

此时恢复成「所有域名共用平台 issuer」的老行为（学校域名的登录会因 discovery 不匹配而不可用，
但平台域名不受影响）。**仅作回滚手段**，新增学校域名时应保持默认的动态 issuer。

## 四、本地开发

### hosts

无需改 `/etc/hosts` —— macOS / Linux 浏览器会把 `*.localhost` 直接解析到回环。

```bash
# 直接访问
http://qidi.localhost:4200/
```

如需其它域名，在 `/etc/hosts` 加一行即可：

```
127.0.0.1 qidi.iketong.localhost
```

### 平台基础域名（本地）

管理端 → 学校设置 → 平台设置 · 域名绑定 → 基础域名填 `localhost`，
学校配 `Slug = qidi`，即可用 `http://qidi.localhost:4200/` 访问。

> 想在本地模拟生产的 iketong 子域名：基础域名填 `iketong.com`，
> 再用 `curl -H "Host: qidi.iketong.com"` 打 API 即可验证解析链路
> （浏览器访问需在 hosts 里把 `qidi.iketong.com` 指到 127.0.0.1）。

### dev server 代理

`angular/proxy.conf.js` 已统一：

- `changeOrigin: false` —— 保留浏览器原始 Host，域名才能传到后端；
- `X-Forwarded-Proto: http` —— 让 `/api` 与 `/connect` 推导出的 issuer 一致
  （否则登录后立刻 401 掉线）。

> 改完 `proxy.conf.js` 需要重启 dev server（`./dev.sh restart angular`）。

## 五、验证清单

以学校域名 `qidi.iketong.com` 为例：

| 检查 | 命令 / 位置 | 期望 |
|---|---|---|
| 域名解析 | `GET /api/public/current-tenant` | `isSchoolDomain=true`，返回本校 id / 名称 / 徽标 |
| 门户收敛 | `GET /api/app/portal/public-tenant-list` | 只返回本校 1 条 |
| 租户清单收敛 | `GET /api/public/tenants` | 只返回本校 |
| 登录可用 | 用本校账号登录 | 成功，进入本校工作台 / 学生门户 |
| 跨校账号 | 用别校账号登录 | 登录被拒 + 「用户名或密码无效！（当前站点为「XX」的专属域名，请使用该学校的账号登录）」 |
| 平台域名不受影响 | 在 `www.iketong.com` 上重复上述 | 租户清单返回全部，机构下拉可选任意租户，host 管理员可进工作台 |
| 令牌 issuer | `/.well-known/openid-configuration` | `issuer` = `https://<当前域名>/` |

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 学校域名下首页仍显示所有学校 | 后端未重启 / 迁移未应用 | 重新应用迁移 `20261024031912_AddSchoolDomainBinding` 并重启 API |
| 学校域名下 `isSchoolDomain=false` | 学校没配域名，或基础域名不含该后缀 | 检查 `/admin/school` 的域名配置与 `BaseDomains` |
| 刚配好域名仍不生效（最多 10 分钟） | 该主机名此前被缓存为「未命中」 | 保存学校档案时会主动失效新域名对应缓存；若手工改库则等 TTL 或重启 API |
| 登录后立刻掉线 / 401 | 协议透传不对，issuer 不一致 | 看 discovery 的 `issuer`，核对宝塔与容器 nginx 的 `X-Forwarded-Proto` |
| 在 A 校域名登录后切到 B 校域名被踢回登录页 | **符合设计**：令牌按域名签发，跨域必须重新登录 | 预期行为，非缺陷 |
| 页面一直停在启动闪屏 | 前端资源 404 | 检查宝塔反代到 4200 的路径是否正确（`/` 走静态，`/api` 走 API） |
| 学校域名下打开管理端 401 | 令牌所属租户与域名不一致 | 预期行为，请用本校账号在本校域名登录 |
| 改了域名后旧域名仍生效 | 解析缓存 | 正常最长 10 分钟；保存时会主动失效对应 key |

## 八、部署脚本命令速查

```bash
cd etc/docker

./deploy-iketong.sh bt-site                       # 只重建宝塔站点（含学校域名）
./deploy-iketong.sh bt-ssl                        # 只申请/续签证书（含学校域名 SAN）
./deploy-iketong.sh bt-school-domain qidi.iketong.com   # 接入一个新学校域名（站点+证书+环境变量）
```

`bt-school-domain` 会自动把域名追加进 `.env.iketong` 的 `SCHOOL_DOMAINS`，
下次 `deploy-iketong.sh all` 也会带上。

**接入后仍需在管理端做两步**（脚本不碰业务数据）：

1. 学校设置 → 平台设置 · 域名绑定 → 基础域名填 `iketong.com`；
2. 学校设置 → 对应学校 → 子域名前缀填该域名的前缀（`qidi.iketong.com` → `qidi`）。
