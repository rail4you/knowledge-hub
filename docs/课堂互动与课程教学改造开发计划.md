# 课程教学改造开发计划（P0 + P1）

> 依据：`docs/kg-edu课程功能对比与移植建议.md` 的差异矩阵。
> 本计划**只做 P0 + P1 共 12 项**；P2（能力体系、AI 教研、XMind/OPML 导入、教师级门户）与**知识图谱**不在范围内。
>
> 技术基线：ABP 10 / .NET + Angular（standalone + signals + OnPush）/ PostgreSQL（`localhost:5433`）。
> 表名前缀 `App`（`KnowledgeHubConsts.DbTablePrefix`）。

---

## 0. 范围与不做的事

| 做 | 不做 |
|---|---|
| 课程教学信息 + 教材（P0） | 知识图谱可视化、图谱自动生成（`KnowledgeGraph` 模块保持"暂不实现"） |

## 3. 三个必须先落地的公共设施

### 3.1 知识点体系统一（T3/T4 的地基）

现状：`Courses.KnowledgeResource`（课程知识点树）与 `LearningAnalytics.KnowledgePoint`（试卷分析知识点）
**代码零交叉**；掌握度也有两套算法。直接移植推荐/画像会变成第三套。

**方案（最小改动，4 步）**

1. `Courses.KnowledgeResource` 为唯一主数据；补 `SortPath` + `NodeType`（admin 端树维护用）。
2. `LearningAnalytics.KnowledgePoint` 增可空 `KnowledgeResourceId`；`KnowledgePointExtractor` 落库时按
   「同章节 + 名称归一化 + 向量最近」尝试自动挂接，灰区进「知识点治理」页人工确认（页面已存在）。
3. 掌握度只保留 `LearningAnalytics.MasteryCalculator`（Beta 先验 + 120 天半衰期）。
   `Learning.KnowledgeMastery` 降级为**物化缓存**：字段改 `Mastery`/`Evidence`，
   `RecordPractice` 的"3 次且 ≥80% → Mastered"逻辑删除，改由 `MasteryRecalculationService` 统一写。
4. 推荐、画像、能力达成度（P2）全部读这一步的结果。

**风险控制**：映射先跑 dry-run（只写日志不落库），人工抽检 20 个知识点确认后再开自动挂接。

### 3.2 Token 免登录会话基础设施（T5–T8 共用）

kg-edu 的结论（读它的 `student/check-in.tsx` 得到）：**token 链接"看"是匿名的，"提交"要求登录**，
未登录点提交会跳登录并带 `redirect` 回跳。KH 照这个语义做，能省掉一半鉴权设计。

**关键设计：token 里不带 tenantId。**

离 URL 不带租户 → 不需要 `__tenant` 头/cookie → 天然避开项目里那个「`__tenant` 残留 cookie 导致
门户显示成另一所学校」的坑。

```
POST /api/app/classroom-token/resolve   （匿名）  { token, kind }
  → 服务端用 DataFilter.Disable<IMultiTenant>() 按 token 查会话行，
    拿到 Session.TenantId 后 using (CurrentTenant.Change(tenantId)) 再读业务数据
  → 返回 { kind, tenantId, tenantName, sessionId, title, status, courseId, ... }
```

实现要点：

- token = `RandomNumberGenerator` 22~32 位 URL-safe 字符串；`Token` 列加**唯一索引**。
- 读取端点 `[AllowAnonymous]`；`KnowledgeHubAppService` 基类已有 `[IgnoreAntiforgeryToken]`（类级），
  但**匿名 POST 仍要显式写 `[AllowAnonymous]`**，否则被 antiforgery/授权中间件拦成 400（项目里 `SearchAppService` 是同类先例）。
- 提交端点不做匿名：登录后校验 `CurrentTenant.Id == session.TenantId`，不等返回 400「不属于本场次」。
- 前端 token 页面**不挂** `authGuard`，也不要挂 `studentPortalGuard`（它的语义是"学生门户公开可浏览"，
  外面再叠 `authGuard` 会互相抵消——`app.routes.ts:56` 有这条注释）。
- 二维码短链（`layout: eLayoutType.empty`）：

  | 用途 | 路径 |
  |---|---|
  | 签到 | `/check-in/:token` |
  | 讨论 | `/discussion/:token` |
  | 小组任务 | `/group-task/:token` |
  | 课堂练习 | `/classroom-practice/:token` |

  放 `app.routes.ts` 顶层（`path: 'student'` 布局路由的 children 不匹配时会继续向下匹配，所以不冲突）。

## 8. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| 知识点双轨没统一就上推荐 | 学生端出现两套矛盾掌握度 | B1 的 T4 未验收前**不启动 T12**；映射先 dry-run |
| 顶级 order 用了小数 | 「课堂互动」分组随机漂到侧边栏末尾 | 只用整数；改完在 3 个浏览器/2 次刷新下核对顺序 |
| 匿名 POST 被 antiforgery 拦 | 短链页面 400，curl 却正常 | 匿名方法显式 `[AllowAnonymous]`；基类已有 `[IgnoreAntiforgeryToken]`，但**别只依赖基类** |
| 视频播放复用资源预览端点 | 学生 403（资源未过审/库不可见） | 单独 `stream` 端点 + 课程鉴权（T9 已定） |
| token 猜解/遍历 | 越权看别的班级签到名单 | token 22+ 位加密随机 + 唯一索引；resolved 端点只回会话元信息（**绝不含名单**） |
| 活动日志把主流程拖慢/搞挂 | 作答失败 | 异步 + try/catch + 不加入 UoW |
| 新 `DbSet` 漏加 | 运行时注入 `IRepository<,>` 报 500 | 每张新表的 checklist 第一项就是 DbSet |
| 菜单/权限只加菜单不加权限定义 | 运行时 "AuthorizationPolicy not found" | 权限定义 + `RolePermissionSeeder` 三处授权一起改 |

**回滚策略**：12 次迁移，每批一个 commit，迁移只做加法（加表/加可空列），
不做删列/改名 → 出问题直接 `git revert` + 回退到上一个镜像，脏数据留在新表里不影响老功能。

|---|---|
| 视频存储 | 本站 FileStorage（`uploads/course-videos/{courseId}/`）+ 一条 **私有 Draft Resource** 承载文件元信息；**不引 Mux / 第三方点播** |
| 播放鉴权 | **按课程可见性**（本课教师 / 有 `Courses.Video`、`Courses.Edit` 权限 / 已选课学生），与资源库审核状态解耦。挂进课程的视频属于课程内容；要进资源库共享仍需走原审核 |
| 为什么不用 `/api/resource-file/{id}/preview` | 那个端点按审核状态 + 库可见性鉴权，会把课程内视频挡成 403；且 `IRemoteStreamContent` 不支持 Range，拖不动进度 |
| 播放端点 | `GET /api/course-video/{id}/stream`（`PhysicalFile` + `enableRangeProcessing`）；外链视频 302 到 `ExternalUrl` |
| 视频时长 | **服务端不跑 ffmpeg 探测**：前端 `loadedmetadata` 拿到真实时长后 `PUT .../{id}/duration` 回填 |
| 时间轴打点 | 秒级；`(CourseVideoId, PointSec)` 唯一索引，同秒重复打点＝更新而非新增 |
| 删视频 | 同时删标记 + 私有 Draft Resource + 磁盘文件；非 Draft（已进资源库）的 Resource 不动 |
| 打印 | Gotenberg Chromium（`/forms/chromium/convert/html`），A4 由 CSS `@page` 声明；边距 12mm；`printBackground=true` |
| 下载方式 | 前端用 `AuthFetchService.fetch`（**不带** `Accept: application/json`）+ blob，避免 JSON formatter 抢走 `RemoteStreamContent` |

### 12.3 踩到的坑（已在代码里注释）

1. **`paperWidth`/`paperHeight` 不能传 `"A4"`** —— Gotenberg 这两个字段只接受**英寸数值**，传 `A4` 直接 400（`strconv.ParseFloat` 失败）。纸张尺寸改用 CSS `@page { size: A4 portrait }`。
2. **含 `IFormFile` 的 DTO 会 415** —— ABP 约定控制器把复杂类型按 JSON 绑定；改成**扁平参数**（`Guid courseId, IFormFile file, string? title...`）才走 form 绑定（与作业上传一致）。生成的 proxy 对 `IFormFile` 也是错的（`body: file`），所以上传用手写 `FormData`。
3. **`Resource` 没有 `(Guid id)` 构造函数** —— `Id` 由 ABP 在 Insert 时 `EntityHelper.TrySetId` 自动生成，不能手写 `Id = GuidGenerator.Create()`（编译报 protected setter）。要插完再读 `resource.Id`。
4. **又是同一 UoW 内"先写再读"** —— 上传后立刻 `GetAsync(video.Id)` 报「不存在 id 的实体 CourseVideo」；`UpdateAsync`/`UpdateDuration` 同理。已统一加 `SaveNowAsync()`。
5. **模板里调 private 方法** —— `(timeupdate)="onTimeUpdate()"` 必须是 public，否则 AOT 报 TS2341；另外播放器用了 `ngModel` 必须 import `FormsModule`。
6. **`abp generate-proxy` 的老三处补丁**（`changePassword`、`StringValues`、`any<AgentMessageChunkDto>`）本次依旧要还原。

### 13.3 回归中发现的**两个真实 Bug**（已修）

**① 知识点新建后 `SortPath` 为空**

- 现象：`POST knowledge-resource` 之后树里新节点 `sortPath=null`，只有整门课 `regenerate-sort-paths` 后才有值。
- 根因：`RebuildPathsAsync` 会**重新查库**（`GetQueryableAsync` 不走变更追踪），同 UoW 内刚插入的节点查不到 → 跳过。
- 修法：`RebuildPathsAsync` 开头先 `CurrentUnitOfWork.SaveChangesAsync()`。
- 这是 AGENTS.md 里记过的**同一类坑第三次出现**（B2 小组任务分组、B3 视频上传各一次）。

**② 老师无法回复讨论答疑**

- 现象：`POST discussion/reply` → 403「未选修该课程，不能参与该课程的互动活动。」
- 根因：`ReplyAsync` 复用 `EnsureEnrolledAsync`，把老师挡在自己建的答疑区外——**答疑区的核心动作就是老师回答**。
- 修法：新增 `ClassroomSupport.EnsureCanParticipateAsync`：本课教师 / 有 `Courses.Edit` 直接放行，其余才要求选课。
  签到 / 课堂练习 / 小组任务**保持严格**（它们写"学生记录"，老师参与会污染名单与统计）。

### 13.4 脚本自身的 7 个坑（已固化在 README）

租户头必须 `Abp-TenantId`（不是 `Abp-Tenant-Id`）／无 body 的 POST 要带 `{}` 否则 415／
当前用户在 `currentUser` 不是 `user`／Python 布尔 `True`≠bash `true`／
`$VAR` 紧跟中文必须写 `${VAR}`（否则 `set -u` 报 unbound）／
表名 `AppChapterExercises`、`AppLearningProgress`（不是 `AppChapterExercise(s)`/`AppLearningProgresses`）／
`AppVideoKnowledgeMarks` 是普通 Entity，没有 `IsDeleted`。

### 15.1 知识点 xlsx 导入

**表格格式**（第 1 行标题、第 2 行表头，与「章节导入」一致，老师不用学两套）

| A | B | C | D | E | F | G | H | I |

规则：

| 规则 | 说明 |
|---|---|
| 层级 | A/B/C 建**单元**（可嵌套 3 层），D 建**知识项**（叶子 = 掌握度与练习的最小粒度） |

| 幂等 | **同一父级下同名复用**：重复导入不产生重复节点（补数据可以放心多次导） |
| 复用时只补空 | 只补空的章节/描述/标签，**不覆盖**老师手改过的内容 |
| 章节绑定 | E 列按**标题**匹配本课已有章节；匹配不到只记 warning，不阻断整批 |
| 重要度 | `core/important/normal` 或 `核心/重要/一般` |
| 难度 | 1~5，超范围夹紧 |
| 格式 | **只支持 .xlsx**；`.xls` / XMind / OPML 一律明确报错 |

**接口**：`POST knowledge-resource/import-from-excel/{courseId}`（multipart，字段 `file`）、
`GET knowledge-resource/import-template`（xlsx，含 2 行示例 + 填写说明页）
**实现**：`KnowledgeResourceExcelImporter`（解析 + 建树 + 幂等复用 + 导入后重算 `SortPath`），
`KnowledgeResourceAppService` 只做权限与入口；前端在知识点树页工具栏「导入 Excel / 下载模板」。

**实测**（模板自带的示例行：3 行数据）

```
首次导入：数据行 5（模板含 3 行示例，其中 1 行只建单元）
         单元 3 / 知识项 3 / 重算路径 6
重复导入：新增 0 / 复用 9        ← 幂等
.xls   ：400「只支持 .xlsx 格式（不支持 XLS / XMind / OPML）」
树结构  ：导入测试-立体构成 → 材料 →（人工材料/天然材料）
                           → 肌理 →（触觉肌理 / 子类 → 视觉肌理）   ← 三级单元生效
```

### 15.2 岗位能力图谱

**来源**：kg-edu 的 `job_competency_graph` / `job_core_task` / `job_task_ability` / `ability_knowledge_link`。

**移植时的关键简化**：kg-edu 有独立的一张"岗位能力表"（`JobTaskAbility`），
KH 里**改为复用能力体系的能力项**（`Competencies.Competency`）。理由：
否则「岗位能力」和「毕业要求指标点」会是两套互不相干的能力，而知识点只挂在能力体系那一侧，
达成度永远算不出来。复用它之后，岗位图谱天然获得「能力 → 课程知识点 → 掌握度」这条链。

| 表（迁移 `AddJobCompetencyGraph`） | 作用 | 约束 |
|---|---|---|
| `AppJobCompetencyGraphs` | 岗位（`Title`/`MajorId`/`JobPostingId?`/`Version`/`IsActive`） | — |
| `AppJobCoreTasks` | 核心工作任务（`Weight` 表示任务占比） | — |
| `AppJobTaskCompetencies` | 任务 → 能力（`Weight` 支撑强度 / `RequiredLevel` 0 了解 1 熟练 2 精通） | `(CoreTaskId, CompetencyId)` 唯一 |

**接口**（`/api/app/job-competency-graph/*`）：列表 / 详情（可带 `courseId` 出达成度）/ 覆盖度 /
图+任务+关联的 CRUD（`Employment.ManageJobGraph`）

**覆盖度口径**（老师在页面上最需要的两个数）
- **能力可测率** = 已挂课程知识点的能力数 / 涉及能力总数（0% 意味着还算不出达成度）
- **缺口**：被任务引用但没挂知识点的能力名 + 没挂任何能力的任务数
- 传 `courseId` 时额外给「该课程对岗位能力的整体达成度」（复用 `CompetencyAppService.GetAchievementAsync`）

**前端**：`/admin/employment/job-graphs`（列表：任务数/能力数/可测率）
+ `/admin/employment/job-graphs/:id`（详情：三张指标卡 + 缺口提示 + 每个核心任务一张卡，任务内列能力与达成度；
可加/改/删任务、给任务挂能力、解除关联；顶部可选课程看达成度）

### 15.3 验证结果

| 重复导入 | 新增 0、复用 9（幂等） |
| 三级单元 + 孤儿知识项 | 都能正确落库并算出 `SortPath`（`0001.0002.0002.0001`） |
| 非 xlsx | 400 且文案明确 |

### 15.4 补记两个坑

1. **能力项编码必须带 RUN_TAG**：`(MajorId, Code)` 唯一索引在 `MajorId IS NULL` 时 Postgres 认为 NULL 互不相等
   → 固定编码 `E2E-1` 每次跑都插一条新记录（实测堆了 3 条）。现在 e2e 用 `E2E-${RUN_TAG}`，cleanup 按 `Code LIKE 'E2E-%'` 清。
2. **e2e 早先的知识点断言要限定对象**：P2-3 会往同一门课导入节点，
   原来「单元数=1 / 知识项数=2」这类全课计数必然失败 —— 改为按 B1 建的节点名过滤（`回归单元` / `回归知识项%`）。

### 18.4 推荐落地（A9）

**新表** `AppStudentRecommendations`（迁移 `AddStudentRecommendation`）：

| 字段 | 说明 |
|---|---|
| `Type` | 薄弱知识点(0) / 前置知识(1) / 未完成章节(2) / 学习节奏(3) |

| `Priority` / `Reason` / `MetricValue` | 1~10 优先级、**可解释的理由**、生成时的数值快照 |
| 去重 | (`StudentId`,`CourseId`,`Type`,`KnowledgeResourceId`,`ChapterId`) 唯一（过滤空值） |

**生成三源**（全部复用已有数据，不新造指标）
1. **薄弱知识点**：`Mastery < ThresholdResolver(courseId).Weak` 且有证据 → 取最低 3 个，掌握度越低优先级越高（9 / 7）；
2. **前置知识**：`KpPrerequisite`（Confirmed）—— 映射未跑通前**不硬推**（避免推错点污染体验），留接口；
3. **未完成章节**：`LearningProgress < 100%` 且近 14 天无该章节活动 → 顶层章节最多 8 个（**同名章节去重**，见踩坑）。

**生命周期规则**：已忽略 / 已完成的推荐**不会被重新生成复活**（尊重学生选择）；未处理的重算时只更新理由与优先级。

**接口**：`my` / `{id}/mark?status=` / `refresh-mine/{courseId}` / `refresh-course/{courseId}` / `course-overview/{courseId}`
**页面**：教师 `/learning/recommendations`（分布 + 采纳率 + 学生清单 + 一键刷新整课）；学生 `/student/recommendations`（卡片 + 去练习/去学习 + 完成/忽略）

### 18.5 踩到的坑

1. **导出流被提前释放**（见 18.3）——`RemoteStreamContent` + `using var stream` 必然 500。
2. **同名章节产生两条一模一样的推荐**：测试课程因重复导入存在同名顶层章节 → 推荐列表出现"还没开始 / 已学 10%"两条。
   已按 **章节标题去重**（保留进度最高的一条）。
3. **`LearningProgress.Progress` 是 decimal**：直接传给 `double?` 参数编译失败，必须先 `(double)` 转换再算出百分比。

### 19.6 布局优化：双栏占满页面高度、两栏等高

**问题**：`.jg-layout` 用了 `align-items: start`，两栏各自按内容撑高 → 高度不齐；左栏只有 `max-height`、右栏只有 `min-height: 420px`，都没吃满页面。

**改法**（沿用项目里 `case-analysis` / `live-room` 的"定高 + 内部滚动"范式）：

| 元素 | 关键样式 | 作用 |
|---|---|---|
| `.jg-container` | `height: calc(100vh - 120px)` + `min-height: 640px` + flex 列 | 页面锁到视口高度（减顶部导航），不给内部留"自然撑开"的机会 |
| `.jg-layout` | `align-items: stretch` + `flex: 1 1 auto` + `min-height: 0` | 两栏**等高**并吃掉页头之外的剩余高度 |
| `.jg-left` / `.jg-right` | `height: 100%` + `min-height: 0` + flex 列 + `overflow: hidden` | 作为 flex 子项能正确收缩（不加 `min-height:0` 会被内容顶开） |
| `.jg-jobs`（左侧列表） | `flex: 1 1 auto; min-height: 0; overflow-y: auto` | **只有岗位列表滚动**，搜索框固定 |
| `.jg-right__body` | `flex: 1 1 auto; min-height: 0; overflow: auto` | 图谱区占满右栏剩余高度，图谱宽/高超出时**在右栏内部滚动** |

结果：页面本身不滚动，左右两栏各自滚动，底部对齐；统计/图谱再多也不会把页面拉长。

**窄屏（≤1000px）**：取消定高改为纵向堆叠（`.jg-layout` / `.jg-right` 走 `height: auto`，
左栏 `max-height: 42vh`、右栏 `min-height: 420px`），否则 `height:100%` 在 grid 的 auto 行里会塌陷。
