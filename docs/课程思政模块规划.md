# 课程思政模块 · 规划（待确认后开发）

> 原型：`~/Downloads/课程思政模块原型.html`（5 个页签：案例库 / 思政图谱 / 教案融入 / 覆盖分析 / 功能总结）
> 目标：按 ABP 模块化方式实现，**可插拔**（按需绑定到课程体系），**可整段移除且不影响课程主流程**。

---

## 0. 一句话方案

新增一个**自包含的 `CourseIdeology` 模块**：只新增自己的表、自己的权限、自己的菜单/路由，
对核心 `Course` / `CourseLessonPlan` **不加任何字段、不改任何现有 DTO**，
绑定关系全部由模块自己的表持有（`CourseId` / `LessonPlanId` 外键指过去）。
整体开关走 ABP **Feature**（`KnowledgeHub.CourseIdeology`），课程级开关走模块表。

## 3. 数据模型（7 张表，全在模块内）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `AppIdeologyElements` | 思政元素体系（学校/学科可定制） | Code、Name、Category（家国情怀/法治意识/…）、Description、SortOrder、IsEnabled |
| `AppIdeologyCases` | 思政案例 | CourseId?（null = 全校共享）、ChapterId?、Title、Summary、ContentJson（结构化：切入点/梗概/讨论问题/融入建议）、SourceType（教材/权威媒体/法规/校企/AI）、**SourceText（出处，必填）**、SourceUrl、SourceDate（时效提醒用）、UsageMethod、Status、AiGenerated、AiTaskId?、ReviewComment、SubmittedAt、PublishedAt、CreatorName、ReferenceCount |
| `AppIdeologyCaseElements` | 案例 ↔ 元素（多对多） | CaseId、ElementId |
| `AppIdeologyCaseAudits` | 审核留痕（对齐 `NewsAudit` 写法） | CaseId、FromStatus、ToStatus、Action、Comment、OperatorId |
| `AppCourseIdeologySettings` | **课程级绑定开关** | CourseId（唯一）、IsEnabled、IdeologyGoal（课程思政总目标）、Note |
| `AppIdeologyLessonPlanInsets` | 教案融入明细 | LessonPlanId、CaseId?、ElementId?、Position（导入/讲授/实训/小结…）、CustomTitle、CustomContent、SortOrder |
| `AppIdeologyReflections`（P4） | 学生思政反思/课堂讨论 | CaseId、StudentId、Content、SubmittedAt、TeacherComment |

枚举：`IdeologyCaseStatus`（Draft 0 / Submitted 10 / DepartmentApproved 20 / Published 30 / Rejected 40 / Archived 50）、
`IdeologySourceType`、`IdeologyUsageMethod`、`IdeologyInsetPosition`。

**绑定点只有两处**：`AppCourseIdeologySettings.CourseId`、`AppIdeologyLessonPlanInsets.LessonPlanId`（都是模块表内的外键，删表即解耦）。

## 7. AI 生成（接入现有 AI 任务框架）

- `AiTaskType.CourseIdeologyCase = 70`、`AiFeatureGroups.IdeologyCase`
- 输入：`courseId`、`chapterId`、`elementIds`、`material`（教师粘贴的权威素材/链接）、`usageMethod`
- Prompt 硬约束（防"编事实"）：
  1. 只能基于教师提供的素材与可核查的公开事实，**不得虚构数据/人名/时间**
  2. 输出结构化 JSON：切入点 / 案例梗概(≤300字) / 讨论问题(2~3个) / 融入建议(含时长) / 出处
  3. 自动打标 `待核验`、`时政时效待确认`
- 落库：`IdeologyCase` 状态固定 **Draft** + `AiGenerated=true` + `AiTaskId`（可追溯），**不允许直接发布**
- 用量/配额沿用现有 `AiUsageTracker`（新分组）

## 8. 可插拔 / 可移除方案

### 三层开关

| 层 | 手段 | 关闭后的表现 |
|---|---|---|
| ① 模块总开关 | ABP Feature `KnowledgeHub.CourseIdeology`（默认 `false`） | 菜单/路由/卡片全部不注册；直接访问 URL 被 `FeatureGuard` 拦；Host 在「功能管理」里按租户开通 |
| ② 课程级绑定 | `AppCourseIdeologySettings.IsEnabled` | 该课程不出现思政入口；已有数据保留但只读（管理页可重新开启） |
| ③ 单条案例 | `Status`（Draft / Rejected / Archived） | 只影响覆盖统计与教案推荐 |

### 移除清单（写在 `docs/课程思政-移除说明.md`，5 分钟可做完）

1. 删迁移（`dotnet ef migrations remove` 或执行 `Down`）→ 6~7 张表
2. 删 5 个文件夹（Domain / Contracts / Application / EF / Angular 页面目录）
3. 删 4 处注册：Feature 定义、权限定义、菜单 provider 注册、`app.routes.ts` 3 条路由
4. 删工作台卡片 1 张、教案页区块 1 行
5. 核心 `Course` / `LessonPlan` 无需回滚（无字段变更）

## 10. 风险与取舍

1. **两级审核需要新角色**：本系统目前没有「教研室主任 / 学院思政负责人」角色。P0 先把两级权限做成两个权限（`.Review` / `.FinalReview`）都授予 `SchoolAdmin`，等角色体系扩展后再拆分角色，避免为了一个模块动角色体系。
2. **图谱不引入图表库**：原型是确定性三层布局，自绘 SVG 足够，避免为演示加 d3/echarts 依赖（也更好做暗色主题与中文排版）。
3. **案例是"课程级"还是"共享级"**：`CourseId` 可空 = 全校共享案例；课程页只显示 `本课程 + 共享`，避免每个老师重复建同一案例。
4. **AI 合规**：原型明确"案例须人工核验"。我们**不允许 AI 直接发布**，草稿必带 `待核验` 标；出处字段后端强校验（必填且 ≥8 字符），防止空出处入库。
5. **教案融入不改教案表**：用独立关联表，`LessonPlan` 删除时关联自动清理（应用层），不影响教案功能。
6. **"如果去掉这个模块也没影响"** 的验证方式：P0 结束时做一次「关 Feature → 全站回归冒烟」，作为验收项写进脚本。

## 13. 已确认的决策（2026-11-25，按用户确认后实施）

| 决策点 | 结论 | 对实现的影响 |
|---|---|---|
| 案例归属 | **思政内容一律强绑课程**（`CourseId` 必填，章节可选） | 无"全校共享案例"；`IdeologyCase.CourseId` 非空 |
| 审核 | **不做审核流**，老师自建自用 | 状态只有 草稿/已发布/已下架；删除审核表与审核接口；老师保存即发布（也可存草稿） |
| 报告导出 | **xlsx**（ClosedXML，4 个 Sheet） | 不再做 CSV/PDF 导出 |
| 学生端 | **本期不做** | 无反思/讨论表；P5 学生端部分整段取消 |
| 思政元素体系 | **可配置**（租户级，默认种子 6 个） | 元素管理弹窗 + 唯一索引 `TenantId+Name` |
| AI 生成 | **本期就上** | `AiTaskType` 方案不用了，改为**同步**调用（老师等 5~15 秒拿草稿），留痕用 `AiGenerated + AiMaterial` |

实施与规划的两处偏差（有意为之）：

1. **AI 生成用同步接口**而不是异步 AI 任务：单个案例就是一次 LLM 请求，
   建任务 → 轮询 → 回列表找结果的链路对"写一条案例"来说太重；
   留痕靠 `IdeologyCase.AiGenerated` + `AiMaterial`（素材快照）。
2. **图谱"手工增删关联"复用案例编辑接口**：关联的唯一事实来源是案例本身
   （改章节 = 改 `ChapterId`，改元素 = 改 `ElementIds`），图谱接口只读，
   避免出现"图谱表里有边、案例里没有"的双写不一致。
