# 资源双向共享：课程资源 ⇄ 教学资源库资源（最终方案 + 落地记录）

> 适用范围：`Resource`（文件资源）、`CourseResource`（课程挂载）、`ResourceLibraryResource`（库挂载）、`CourseSharedRef`（跨校引用）。
>
> **决策已定（2026-11）**：课程资源与教学资源库资源是**两套独立记录**，互转 = **复制一份新记录并带来源标记**；两侧各自维护、互不同步。跨校引用仍走既有的 `CourseSharedRef`（固定版本 + 显式升级）。
>
> 本文记录：为什么这样定、数据模型与接口、已实现部分（资源互转 Tab / 来源列）、以及还没做的部分。

---

## 一、口径（产品语言 → 数据语言）

| 产品说法 | 含义 | 数据 |
|---|---|---|
| **课程资源** | 教师基于某门课程创建/上传的资源 | `Resource` 一行 + `CourseResource(CourseId, ResourceId)` 挂载 |
| **教学资源库资源** | 独立于课程的共享资源（公共网盘式） | `Resource` 一行 + `ResourceLibraryResource(LibraryId, ResourceId)` 挂载 |
| **互转** | 课程资源 → 库资源 / 库资源 → 课程资源 | **新建一条 `Resource` 副本**，写 `SourceType + SourceResourceId + SourceCourseId/SourceLibraryId` |
| **跨校引用** | B 校把 A 校库内容放进自己课程 | `CourseSharedRef`（固定 `ContentVersionId`，可撤销/升级） |

三条硬规则：

1. **库资源不绑定课程**：库里的资源可以完全独立存在（不挂在任何课程上）。
2. **课程资源不直接共享**：课程里的资源不会"变成"库资源；要进库必须走「互转」（生成副本 + 准入审核）。
3. **互转产生的两侧是两份记录**：改一边不影响另一边；需要最新内容时**再转一次**（来源字段保证可追溯）。

## 二、为什么选「复制」而不是「引用同一份」

（曾评估过引用方案：同一 `Resource` 被课程与库同时挂载。结论：不采用，理由如下。）

| 维度 | 引用（同一份） | 复制（当前方案） |
|---|---|---|
| 与产品口径 | 冲突：两端永远是"同一份东西"，没法真正做到"分开处理" | **一致**：课程资源与库资源是两类资源 |
| 修改权限 | 教师在课程里改一下，库里的内容跟着变（或反过来），"谁的内容"说不清 | 各改各的，边界清晰 |
| 审核 | 一处通过、处处生效，或需要复杂的版本指针 + 重审 | 副本各自走审核，规则简单、可解释 |
| 删除/下架 | 需要级联撤销多个挂载点，且有"删了别人的课"的风险 | 删自己那份，另一侧不受影响（来源字段保留血缘） |
| 缺点 | — | 存储与 AI 索引会有副本（成本 ×N）、更新不同步 |

**成本的应对**：

- 副本只在**显式点「转入」**时产生，不做隐式复制；
- 来源字段（`SourceResourceId`）保证"这份是从哪转来的"，需要最新版时**重新转一次**即可；
- 后续可加「来源有新版本」提示（按 `SourceResourceId` 对比 `CurrentVersion`），但**不做自动同步**（自动同步会重新引入引用方案的复杂度）。

## 三、数据模型（已实现）

```csharp
// Domain.Shared/Resources/Enums/ResourceSourceType.cs
enum ResourceSourceType : byte { Created = 0, FromCourse = 1, FromLibrary = 2 }

// Domain/Resources/Resource.cs（新增 4 个字段）
SourceType        ResourceSourceType   // 默认 Created
SourceResourceId  Guid?                // 转换前的源资源（血缘，不参与同步）
SourceCourseId    Guid?                // FromCourse 时：来源课程（「来自课程：X」）
SourceLibraryId   Guid?                // FromLibrary 时：来源资源库（「来自资源库：Y」）
```

- 索引：`SourceType`、`SourceResourceId`；
- 迁移：`20261108123433_AddResourceSourceFields`（已应用到本地库）；
- 转换生成的副本：`Status = PendingReview`、`CurrentVersion = 1`、复制当前版本文件并新建 `ResourceVersion`，`MediaStatus = None`（预览/索引按既有流程在审核后生成）。

## 四、接口（已实现）

`IResourceConversionAppService` → `/api/app/resource-conversion/*`

| 方法 | 路由 | 权限 | 说明 |
|---|---|---|---|
| `GetCourseResourcesAsync` | `GET /course-resources?courseId=&filter=` | `KnowledgeHub.Courses` | 「互转」左栏：某课程的课程资源（含来源、创建人、已关联库） |
| `GetLibraryResourcesAsync` | `GET /library-resources?libraryId=&filter=` | `KnowledgeHub.ResourceLibraries` | 「互转」右栏：某库的库资源（含来源、归属学校） |
| `ConvertToLibraryAsync` | `POST /convert-to-library` | `KnowledgeHub.ResourceLibraries.Build` | 课程资源 → 库资源：校验库可挂载 → 复制 → 建 `ResourceLibraryResource` → 若开审核则 `BeginAdmissionAsync` |
| `ConvertToCourseAsync` | `POST /convert-to-course` | `KnowledgeHub.Courses.Edit` | 库资源 → 课程资源：校验课程可编辑（负责人/本校管理员/主建库管理员）→ 复制 → 建 `CourseResource`；跨校源必须已在该库发布 |

**权限要点**

- 转进库：目标库必须"本校主建 or 参与共建"（复用 `IResourceLibraryAttachmentValidator`）；源资源必须本校。
- 转进课：课程必须本人负责（或本校/主建库管理员）；他校库资源需 `ResourcePublication = Published`。
- 副本的 `CreatorId` = 操作者、`TenantId` = 当前租户 → 后续编辑/删除天然按"自己创建"处理。

## 五、前端（已实现）

### 5.1 资源管理 → 独立 Tab「资源互转」

`/resources` 页签顺序：**资源列表 · 分类管理 · 资源互转**（权限：`KnowledgeHub.Courses || KnowledgeHub.ResourceLibraries`）。

- 左栏 = 课程资源：选课程 → 列出**你自己新建、且审核通过**的课程资源（名称/大小/创建人）。过滤器：
  1. 只显示 `SourceType = Created`（新建）且 `CreatorId = 当前用户`（管理员不限）——从资源库转来的副本不参与二次共享；
  2. 只显示审核通过（`SchoolApproved` / `LeagueApproved`）；
  3. **「已共享」按目标库逐库判断**：全部行都可勾选；只有「已在当前选中的目标资源库共享过」的行会被禁用并标注「已在该库共享」，
     其它库的共享情况只用信息标签「已在：X」提示（不同库允许各共享一份）。
  4. 后端 `ConvertToLibraryAsync` 同样按目标库判重：同一库重复共享返回 403「该资源已在「X」共享过，无需重复共享」；不同库允许；
- 右栏 = 教学资源库资源：选资源库（只列"我的库"）→ 列出库资源（名称/来源/大小/归属学校）；
- 双向按钮：`转入资源库 →`（用左栏勾选 + 右栏选中的库）、`← 转入课程`（用右栏勾选 + 左栏选中的课程）；
- 批量勾选、逐条调用后端、结束统一提示；转换后两侧自动刷新。

### 5.2 「来源」列

- `/resources` 资源列表新增**来源**列：`新建` / `来自课程：X`（蓝）/ `来自资源库：Y`（紫）；
- 教学资源库工作台「库内容」新增**来源**列（仅文件资源显示，课程/实训为 —）。

> 注：`ResourceDto` / `TeachingLibraryContentDto` 的新字段尚未重新生成 proxy，前端用 `sourceTypeOf()/sourceNameOf()`、`contentSourceType()/contentSourceName()` 读取，重新生成后可去掉这层包装。

## 六、这次改造顺带确认的三条产品决策

1. **跨校引用保持固定版本 + 显式升级**（`CourseSharedRef` 不变）；
2. **内容可改，不要求重审**：修改库内已发布资源的文件**不再**引入 `ChangePending` 重审状态（原方案里的 G2 取消）；
3. **留下来源审计**：`SourceType + SourceResourceId + SourceCourseId/SourceLibraryId` 全量记录。

## 七、仍然存在的技术债（与本次改造正交，建议排期）

| # | 问题 | 影响 |
|---|---|---|
| D1 | `CourseResourceAppService` 读接口（`GetByCourseAsync/GetByResourceAsync`）**无 `[Authorize]`**，匿名可读 | 泄露任意课程的资源清单（已实测匿名 200） |
| D2 | 写接口只有 `Courses.Edit`，**无课程归属校验** | 任一教师可改别人课程的资源挂载 |
| D3 | `Resource.LibraryId`（主库镜像）与关联表可能不一致 | 按库统计/筛选错位 |
| D4 | 删除 `Resource` 无统一级联（挂载 / 发布记录 / 跨校引用） | 悬空挂载、引用方 404 |
| D5 | 库"资源数"统计的是挂载数 | 同一内容多库挂载会重复计数 |

> 互转上线后，副本会**增加**库内内容数，D5 的口径问题会更明显，建议一起修。

## 八、后续可迭代

1. 「来源有新版本」提示（对比 `SourceResourceId` 的 `CurrentVersion`），提供「同步最新版」= 再转一次；
2. 互转记录页（谁在什么时候把哪份资源转到了哪里）；
3. 副本角标视觉统一（现用 `nz-tag` 颜色区分：蓝=来自课程、紫=来自资源库）；
4. 批量转换改为后端一次事务（现在前端串行调用，N 次请求）；
5. 转进库时可选章节/目录（如需按目录归档）。
