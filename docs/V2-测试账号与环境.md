## 4. 典型验证路径（两条，互相独立）

### A. 校内库单级审核（qidi）
1. `qidi-admin` 登录 → `/admin/libraries` 新建资源库 → 状态「待院校审核」
2. 需要第二个人审：用 host `admin` 在 `/admin/libraries/audits` 通过（不能自审）
3. 通过后库变「已发布」；`wwq` 在 `/teaching-resource-libraries` 可见并可共享内容

### B. 共建库两级审核（guozhou）
1. `guozhou-admin` 建「院校共建」库并添加 `qidi` 为关联学校
2. `guozhou-admin` 共享资源入库 → 生成准入审核
3. host `admin` 院校初审通过 → 单据推进到「联盟终审」
4. host `league-admin` 终审通过（**不能是 admin**，会报「联盟终审人不能与院校初审人相同」）
5. `qidi` 的教师可在共建库看到该资源；引用到本校课程后 `zmq` 可学习

### C. 共建任务（guozhou）
1. `guozhou-admin` → `/admin/libraries/tasks` 用模板建任务 → 发布
2. `guozhou-teacher` → `/teaching/build-tasks` 提交交付（会同步生成准入审核）
3. `guozhou-admin` 验收 → 进度 +1（**验收 ≠ 发布**，资源仍需准入审核）

## 4.7 企业用户页面地图（实测）

企业用户（`EnterpriseUser`，如 `ent-demo`）登录后**直达 `/enterprise/workbench`**，侧边栏只保留：

| 菜单 | 路由 | 权限 | 说明 |
|------|------|------|------|
| 系统工作台 | `/admin/workbench` | — | 通用工作台（可后续按角色裁剪） |
| 资源库管理 → 教学资源库工作台 | `/teaching-resource-libraries` | `ResourceLibraries` | 可向本校主建库贡献内容 |
| 资源库管理 → 我的共建任务 | `/teaching/build-tasks` | `ResourceLibraries` | 提交交付物 |
| 资源库管理 → 产教合作 | `/admin/cooperation` | `Cooperation` | 需求大厅（响应是学校侧动作，企业侧主要看） |
| 资源库管理 → 企业工作台 | `/enterprise/workbench` | `Cooperation` | 企业资料/认证、我的需求、项目台账 |
| 资源中心 → 资源管理 / 智能搜索 / 搜索历史 | `/resources` `/search` `/my/search-history` | `Resources` `Search` | 只读为主 + 贡献内容 |
| AI 中心 → 智能问答 / 案例分析 / 职业规划 / 任务监控 | `/ai/*` | `AI` | 企业侧可用 |
| 就业管理 → 岗位管理 | `/admin/employment/jobs` | `Employment.PublishJob` | 发布本企业岗位 |
| 就业管理 → 岗位投递和面试管理 | `/admin/employment/interviews` | `Employment.ScheduleInterview` | 面试安排 |

**不会出现**：专业与课程管理、智学分析、实训管理、资讯/双高、平台运维、教学资源库管理（建库页）、共建任务（建任务页）、审核中心以外的审核动作、学校有效期。

## 5. 浏览器验证要点

- 登录页先选「机构」（租户），再输账号密码；**host 账号**走「系统管理员登录」入口
- 切换租户会重新计算权限（菜单、`requiredPolicy`），不要用上一个租户的观感判断
- 若登录后仍停在登录页：确认 `__tenant` 选择正确、API 是否刚重启（token 失效）
