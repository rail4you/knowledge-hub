## 3. 两个验证脚本

| 脚本 | 用途 | 命令 |
|------|------|------|
| `scripts/test/v2-e2e.sh` | **一键全量回归**（105 断言，8 条流程，自带开关前置与数据清理） | `./scripts/test/v2-e2e.sh` |
| `scripts/test/v2-e2e-modules.sh` | **分模块**，供多个模型/多条终端并行 | `./scripts/test/v2-e2e-modules.sh M2` |

两个脚本的关系：`v2-e2e.sh` 是"跑全套"，`v2-e2e-modules.sh` 是"按块跑"。都自带清理，都可重复执行。

## 5. 建议的上手顺序（30 分钟版）

```bash
# 1) 起环境
./dev.sh start

# 2) 环境自检（账号/健康）
./scripts/test/v2-e2e-modules.sh M0

# 3) 跑一遍核心三块（约 1 分钟）
./scripts/test/v2-e2e-modules.sh M1   # 审核内核
./scripts/test/v2-e2e-modules.sh M2   # 准入 + 文件越权（高危）
./scripts/test/v2-e2e-modules.sh M6   # 权限 / AI / 检索

# 4) 需要全量时
./scripts/test/v2-e2e.sh
```

然后按 `V2-测试账号与环境.md` 用 `ent-demo` / `qidi-admin` 登录，点一遍
`V2-验收与回退手册.md` §5 的 27 项（尤其权限类）。

## 6. 常见问题

| 问题 | 答案 |
|------|------|
| 脚本报 `health=000` | API 没启动：`./dev.sh start api` |
| 脚本某用例 FAIL，是产品问题吗 | 先看 `V2-E2E测试手册.md` §10「已知环境限制」；再看 `V2-E2E验证报告.md` 是否记录过同类 |
| 想只验证某一个功能 | 用 `v2-e2e-modules.sh M<x>`，单模块 30~90 秒 |
| 测完环境变脏了 | 两个脚本都会自清理；若中途打断，按模块末尾的清理段手动执行 |
| M5 跑完会不会影响别人 | 不会：脚本会自动续期；但它是唯一改功能开关的模块，建议最后跑 |
| 前后端分别怎么起 | `./dev.sh start api` / `./dev.sh start angular`；完整见 `LOCAL_DEVELOPMENT.md` |
