### 4.1 一个关键正向发现：审核口径已现成

采购多处要求：「**可指定维护人和审核人，同一人时跳过审核，不同人员时审核通过后发布**」。

现有审核内核 `IReviewWorkflow` 实现的恰好是**反向规则**：
「提交人不得审核自己提交的单（`CannotReviewOwn`）」。

也就是说 —— 只需要在 `ReviewWorkflow.SubmitAsync` 增加一个分支：

```
if (maintainerId == reviewerId)  → 直接置为 Published（跳过审核单）
else                             → 走现有 ReviewTicket 流程
```

**这是 G7 里 6 个栏目（22/23/24/27/28 + 25 的上下架）共同需要的能力，
改一处即可全部满足。** 属于「低成本、高得分」项。

## 五、演示环节（本次重点）

### 5.1 采购原文要求

| 项 | 要求 |
|---|---|
| 方式 | **上传视频演示**（非现场操作） |
| 格式 | `X.mp4` 或 `X.avi`，分段压缩为 `X.zip` |
| 体积 | 单文件 ≤ **50M**，全部 ≤ **300M** |
| 时长 | 总计 ≤ **15 分钟** |

**演示内容（4 组 / 7 子项）**

**① 教师教研**
1. 支持教师创建白板并填写主题等基本信息，通过邀请其他教师加入共创
2. 支持在白板中添加、修改和移动文本、图片等内容

**② 名师工作室**
1. 支持成员上传文档、图片、视频资料
2. 领衔人审核通过后在工作室中发布，用户可查看已发布资料

**③ 互动课堂**
- 支持以课表形式展示课程安排，可切换**日、周、月**课表，鼠标悬浮于课程时显示**课程名称、日期、时间和学校**等信息

**④ 课程资源管理**
1. 支持在后台选择**资源所属模块**，填写资源基本信息，上传**视频资源**并提交
2. 前台支持按基本信息的属性筛选资源，查看对应资源列表，进入资源详情页面**在线播放视频**

## 七、技术风险与决策点

| 风险 | 具体问题 | 建议决策 |
|---|---|---|
| **白板实时协同** | 系统**未引入 SignalR**，多人并发编辑冲突处理复杂 | 第一期不做实时；用「保存 + 刷新」演示；中标后按需补 |
| **五级组织改造** | 现有多租户假设「一个租户 = 一所学校」，改五级会牵动**所有查询的数据权限** | **不改租户语义**：学校仍是 `TenantId`；省市区县作为 `OrgUnit` 上级分组，统计沿树汇总 |
| **信创数据库** | EF Core + Npgsql 大量依赖 PG 特性（`jsonb`、`real[]` 向量、`GIN` 索引） | 优先 openGauss（PG 兼容度最高）；达梦需专项评估向量与 jsonb 替代方案 |
| **家长家庭账号** | 与 ABP Identity 单账号模型冲突（家长 + 学生共用一个账号） | 「一个账号多身份」：`FamilyAccount` 绑定多个 `IdentityUser`；或 `IdentityUser.IsParent` + 关联学生列表 |
| **演示可复核性** | 演示是上传视频，但评标可能要求答疑复核 | 演示路径**必须真跑通**，不做纯剪辑拼接；保留可现场复现的演示数据脚本 |

## 八、结论

1. **能打的部分**：特教内核（四类障碍 / 8 种多模态 / IEP / 盲文）、资源共建审核分发统计、
   多格式预览、AI 生成、权限矩阵 —— 采购里最"重"的内容现实已具备，**可直接截图进响应文件**。

2. **最大缺口是骨架，不是页面**：
   - **G1 组织五级**（19/18/31 的根，硬指标）
   - **G7+G8 栏目体系与分类维度**（覆盖 15 项指标）
   这两块不解决，28 项里 **17 项（60.7%）** 会判不满足；反之补齐这两块可一次翻盘 15 项。

3. **一个高性价比发现**：「维护人 = 审核人时跳过审核」这条全项目通用规则，
   现有审核内核只差一个分支，**改一处即可覆盖 6 个栏目**。

4. **演示环节可行且可控**：
   - 只有 ① 白板是实质新建（8~12 人日）
   - ② 可复用审核内核、③ 零新表、④ 几乎现成
   - **演示可用版 23~34 人日 ≈ 3 周（2 人并行）**，其中白板占一半
