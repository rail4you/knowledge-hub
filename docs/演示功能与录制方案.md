# 特殊教育课程教学资源平台 · 演示功能与录制方案

> 面向对象：开发 / 实施
> 目标：按采购「演示要求」交付一段 **≤15 分钟** 的演示视频，覆盖 **4 组 / 7 个子项**
> 关联文档：`docs/特教平台采购对照与演示改造方案.md`（整体对照与缺口分析）

---

## 一、演示交付要求（硬性）

| 项 | 要求 |
|---|---|
| 演示方式 | **上传视频演示**（非现场操作） |
| 格式 | `X.mp4` 或 `X.avi` |
| 压缩 | 分段压缩为 `X.zip` |
| 体积 | 单个文件 ≤ **50M**，全部文件 ≤ **300M** |
| 时长 | 总计 ≤ **15 分钟** |
| 性质 | 视频是**响应文件的组成部分** |

### 1.1 验收要点（评审看什么）

演示是"能不能做到"的证据，评审关注的是**功能是否真实存在**，因此每个子项都必须
在画面中留下**可识别的操作证据**（点击 → 弹窗 → 提交成功 → 前台可见），不能只有静态页面。

## 三、逐项功能设计

### ④ 课程资源管理

#### 现状（可直接复用，无需重做）

| 能力 | 现成实现 |
|---|---|
| 资源上传（含视频） | `POST /api/app/resource` + 分片上传 `chunk-upload/*` |
| 资源类型 | `ResourceType.Video`，媒体处理生成缩略图/预览 |
| 审核提交 | `POST /api/app/resource/submit-for-review/{id}` |
| 审核通过 | 审核中心 `POST /api/app/resource/audit` |
| 前台列表 + 筛选 | 资源中心 `/resources`（已有多维筛选栏） |
| 详情 + 视频播放 | 资源详情页 + `ResourceFileController` 预览/播放 |
| 收藏 / 下载 | 已有 |

#### 待补（唯一的增量）

| 项 | 设计 |
|---|---|
| **「资源所属模块」** | 复用 `ResourceCategory` 顶层作为「模块」：预置 9 个栏目分类（职业教育/融合教育/政策经验/大讲堂/课标教材/教具辅具/家长课堂/学生成长/专题教育）。<br>**不新增表**；资源表单加「所属模块」下拉，写 `CategoryId`（或落 `ResourceCategory` 关联） |
| 表单加模块下拉 | 资源中心新建/编辑表单顶部 |
| 前台加模块筛选 | 资源中心筛选栏加「模块」一项 |

**工作量：2~3 人日**

#### 录制要点

1. 后台进入资源中心 → 新建 → **选择所属模块**（下拉里能看到 9 个栏目名）
2. 填写名称/简介 → 上传一个**真实视频文件**（20~40MB，能看出进度条）
3. 提交 → 提交成功提示 → 列表出现「待审核」
4. 切换到审核账号 → 审核通过（可选，快速带过）
5. 前台 → 选同一模块 + 一个属性（如学段）→ 列表收窄 → 进详情 → **视频真正播放出声/出画面**

### ② 名师工作室

#### 数据模型（新增 2 张表）

```
Studio（工作室）
  Id, Name, Description, CoverUrl
  OwnerTenantId          归属学校（复用租户）
  LeaderUserId           领衔人
  Status                 Draft / Active / Disabled
  PublishedAt
  CreationTime / CreatorId

StudioMember（成员）
  Id, StudioId, UserId, UserName
  Role                   Leader / Member
  JoinedAt
  Status                 Pending（加入申请）/ Approved / Rejected
```

> 阶段划分：**演示版**只需 `Approved` 直通（管理员加人即可）；
> `Pending` 加入申请与审批放到中标后的产品化阶段（指标 29 完整版）。

#### 复用清单（这是本项目复用度最高的一项）

| 需求 | 复用 |
|---|---|
| 成员上传文档/图片/视频 | **`Resource` 实体 + `IFileStorageService` + 扩展名/大小校验 + 媒体处理**；工作室资料 = 打了 `StudioId` 标记的资源 |
| 领衔人审核 → 发布 | **`ReviewTicket` + `IReviewWorkflow`**，把审核人从「院校管理员」换成「工作室领衔人」 |
| 用户在工作室查看已发布资料 | 复用资源库详情页的「已发布内容」列表样式与可见性过滤 |
| 权限 | 新增 `KnowledgeHub.Studios`（View / Contribute / Review / Manage） |

#### 审核链路的设计要点

采购原文：「**领衔人审核通过后在工作室中发布**」——单级审核，无需两级。

```
成员上传资料 → ResourcePublication(PendingReview)
              → ReviewTicket(TargetType=StudioResource, Stage=School 单级)
领衔人通过   → Publication=Published → 工作室前台可见
```

同时按采购通用口径补一条分支（覆盖后续所有栏目）：

```
提交人(维护人) == 审核人 → 跳过审核，直接 Published
否则                    → 走 ReviewTicket
```

> 插入点：`ReviewWorkflow.SubmitAsync`，在 `_policyResolver.ResolveAsync` 之前判断。
> 现有实现是反向规则（`DecideAsync` 里 `CannotReviewOwn` 回避本人），加这一个分支即可。

**工作量：6~9 人日**

#### 录制要点

1. 以**成员**账号进工作室 → 上传 **3 个文件**（文档 pdf / 图片 png / 视频 mp4，各露一次）
2. 切到**领衔人**账号 → 「待审核」列表看到 3 条 → 逐条通过（或有一个驳回用于对比）
3. 切回普通用户 → 工作室页 → 「已发布资料」里能看到刚才 3 个，点开能预览

### ③ 互动课堂（课表）

#### 数据源（**零新表**）

复用现有**课程直播**：

```
RecruitmentLive
  Type = Course（课程直播，区别于招聘直播）
  Title, CourseId, CourseTitle
  ScheduledAt / ScheduledEndAt     ← 课表的时间
  TeacherName
  TenantId                         ← 所属学校（→ School 档案名）
  Status                           ← 已结束的课可带「回放」
```

#### 实现

| 部分 | 设计 |
|---|---|
| 后端 | 新增 1 个只读接口：`GET /api/app/course-live/timetable?from=&to=&tenantId=` → 返回该区间内的课程直播项（含课程名、教师、时间段、学校名、是否有回放）。**无新表、无迁移** |
| 前端 | 新页面 `/admin/course-timetable`（或挂在「课程直播」下的一个视图），三视图：<br>· **日**：按小时的时间轴<br>· **周**：7 列网格（周一~周日）+ 时间行<br>· **月**：月历网格，格内显示当日课程条数 |
| 悬浮提示 | 鼠标悬浮课程块 → tooltip：**课程名称 / 日期 / 时间范围 / 学校**（4 项，正好对应采购原文） |
| 若需一课多时段 | 加 `CourseSchedule` 轻表（1 人日）；演示阶段可不做 |

**工作量：4~6 人日**

#### 录制要点

1. 进入课表页 → 默认「周」视图（画面里能看出 7 列 + 多条课程块）
2. 切到「日」→ 切到「月」→ 再切回「周」（三次切换要出现在画面里）
3. 鼠标**悬浮**某一课程块 → 让 tooltip 停留 2~3 秒（这是采购原文明确点名的能力，必须清晰可读）

### ① 教师教研（白板共创）

#### 数据模型（新增 2 张表）

```
Whiteboard（白板）
  Id, Title, Topic, CoverUrl
  OwnerTenantId          归属学校
  CreatorId, CreatorName
  CanvasJson             画布元素快照（元素数组）
  Status                 Draft / Active
  LastModificationTime

WhiteboardMember（共创成员）
  Id, WhiteboardId, UserId, UserName
  Role                   Editor / Viewer
  InvitedByUserId, JoinedAt
```

#### 画布元素模型（`CanvasJson`）

```json
{
  "version": 1,
  "width": 1600, "height": 900,
  "background": { "type": "image", "resourceId": "…", "url": "…" },
  "elements": [
    { "id": "e1", "type": "text",  "x": 120, "y": 80,  "w": 320, "h": 60,
      "rotation": 0, "content": "教学目标：认识 3 种常见图形",
      "style": { "fontSize": 20, "color": "#203B40", "bold": true } },
    { "id": "e2", "type": "image", "x": 500, "y": 60,  "w": 260, "h": 180,
      "rotation": 0, "resourceId": "…", "url": "…" }
  ]
}
```

#### 实现

| 部分 | 设计 |
|---|---|
| 编辑器 | **Konva.js**（`ng2-konva` 或直接用 `konva` + Angular 封装）：拖拽移动、双击编辑文本、选中后可改样式/删除 |
| 图片元素 | 从**资源中心选已有图片**（省掉上传模块），也可本地上传复用既有分片上传 |
| 保存 | 整份 `CanvasJson` PATCH 回后端（演示级足够；产品化后可做增量/版本） |
| 邀请共创 | 弹窗列本校教师（复用 `GET /api/identity/users?filter=`）→ 勾选 → 写 `WhiteboardMember(Role=Editor)` |
| 共创演示 | **不做 SignalR**：A 账号编辑保存 → B 账号刷新打开看到内容。演示足以证明"共创" |
| 权限 | 新增 `KnowledgeHub.Whiteboards`（View / Contribute / Manage）；非成员只读或无权限 |

**工作量：8~12 人日（不含实时）**；含 SignalR 实时协同 +7~10 人日

#### 录制要点

1. **教师 A** 登录 → 新建白板 → 填「主题」「标题」→ 保存
2. 点「邀请共创」→ 勾选 **教师 B** → 成员列表出现 B（此镜头是子项 1 的证据）
3. 在白板中：**添加**一段文字 → **修改**文字内容 → **拖动移动**一张图片（三个动作都要清楚）
4. 保存 → 退出 → **教师 B** 登录打开同一白板 → 内容仍在（证明持久化 + 共创可见）
5. （可选加分）B 再改一处并保存 → A 刷新看到 B 的修改

> 保证录多遍时数据一致、可随时复原。

## 五、实施顺序与排期

| 阶段 | 内容 | 人日 | 产出 |
|---|---|---|---|
| S0 | 演示数据种子脚本 + 9 个模块分类 | 0.5 | 可一键重建环境 |
| S1 | **④ 课程资源管理**（模块字段 + 前台筛选） | 2~3 | 片段 1（4 分钟素材） |
| S2 | **② 名师工作室**（含「同一人跳过审核」分支） | 6~9 | 片段 2 |
| S3 | **③ 互动课堂课表**（三视图 + tooltip） | 4~6 | 片段 3 |
| S4 | **① 教师教研白板**（画布 + 邀请 + 持久化） | 8~12 | 片段 4 |

| **合计** | | **23~34** | |

**排期**：2 人并行 ≈ **3 周（15 个工作日）**；含白板实时协同 ≈ 4 周。

**顺序理由**：先做改动最小、复用最高的 ④，最快跑通"录屏 → 剪辑 → 分包"全流程；
把风险最大的白板放最后，即使它的工期浮动也不会影响前 3 组按时交付。

## 六、录制与剪辑规范

| 项 | 规范 |
|---|---|
| 分辨率 | 1920×1080，浏览器缩放 100%（保证文字可读） |
| 录屏工具 | 本地录屏（OBS / Mac 自带），**不要**用远程桌面（避免卡顿） |
| 光标 | 开启光标高亮/点击波纹，便于评审跟随操作 |
| 字幕 | 全程中文字幕（说明当前正在演示哪个子项） |
| 分节标题 | 每组前插 3 秒标题卡：「④ 课程资源管理」等，与采购 4 组一一对应 |
| 敏感数据 | 检查画面内无密码、无真实学生个人信息、无内网 IP |
| 分包 | 按 4 组分段导出，每段 ≤50M；总 ≤300M；打包为一个 zip |
| 时长控制 | 按 13 分钟录制，剪辑后 14~15 分钟，留余量 |

## 七、风险与取舍

| 风险 | 应对 |
|---|---|
| 白板工期超预期 | 放最后做；保底方案：只做「文本 + 图片的增/改/移 + 保存」四件事，砍掉样式面板 |
| 「共创」被质疑不是真协作 | 录制时用**两个不同账号**各自登录、各自打开同一白板，画面明确显示两个用户名 |
| 视频上传耗时长 | 用 20~30MB 素材；剪辑时对进度条做**加速播放**（画面标注"已加速"） |
| 课表数据看起来假 | 用真实课程名 + 真实学校名 + 分布于当前周/月的时间，避免全同一时刻 |
| 评审现场复核 | **演示路径必须真跑通**，不做纯剪辑拼接；保留演示数据种子脚本以便现场复现 |
| 包体超标（300M） | 分段导出后逐段检查体积，必要时降低码率（1080p → 8Mbps 足够） |
