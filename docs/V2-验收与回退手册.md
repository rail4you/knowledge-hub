## 2. 功能开关（回退总闸）

| 开关 | 默认 | 作用 | 关闭后的行为 |
|------|:--:|------|------|
| `KnowledgeHub.LibraryReview` | 关 | 资源库/内容走审核 | 建库→草稿、入库→直接挂库（旧行为） |
| `KnowledgeHub.BuildTask` | 关 | 共建任务 | 任务相关接口报「未开通」 |
| `KnowledgeHub.CrossSchoolRef` | 关 | 跨校引用 | 引用接口报「未开通」 |
| `KnowledgeHub.EnterpriseWorkspace` | 关 | 产教合作 | 需求/项目接口受限 |
| `KnowledgeHub.OrganizationValidity` | 关 | 单位有效期门禁 | 不再拦截写操作（有效期字段仍存） |

开关粒度：**按租户**（`providerName=T`）。全部关闭即回到 V1 行为，已有数据保留只读。

```bash

curl -sk -X PUT "https://localhost:44305/api/feature-management/features?providerName=T&providerKey=<tenantId>" \
  -H "Authorization: Bearer <host-admin-token>" -H 'Content-Type: application/json' \
  -d '{"features":[
        {"name":"KnowledgeHub.LibraryReview","value":"false"},
        {"name":"KnowledgeHub.BuildTask","value":"false"},
        {"name":"KnowledgeHub.CrossSchoolRef","value":"false"},
        {"name":"KnowledgeHub.EnterpriseWorkspace","value":"false"},
        {"name":"KnowledgeHub.OrganizationValidity","value":"false"}]}'
```

## 3. 数据库迁移（8 条，全部只增）

| # | 迁移 | 内容 | 破坏性 |
|---|------|------|:--:|
| 1 | `AddReviewKernel` | `AppReviewTickets` / `AppReviewActions` | 无 |
| 2 | `RenameReviewActionOperation` | 列改名 `ActionType`→`Operation`（表当时为空） | 无 |
| 3 | `AddResourcePublication` | `AppResourcePublications` | 无 |
| 4 | `AddLibraryTemplateAndBuildTask` | 模板/任务/交付/库级授权 8 张表 + 库表 3 列 | 无 |
| 5 | `AddCourseSharedRef` | `AppCourseSharedRefs` / `AppResourceUsageEvents` | 无 |
| 6 | `AddEnterpriseAndOrganizationValidity` | `AppEnterpriseProfiles` / `AppEnterpriseMembers` + `AppSchools` 3 列 | 无 |
| 7 | `AddCooperationDemandProject` | 需求/响应/项目/里程碑 4 张表 | 无 |
| 8 | `AddEmploymentEnterpriseSnapshotAndVerification` | 岗位/投递/面试/去向 共 10 个可空列 | 无 |

**原则**：只新增表、只加可空列、只追加枚举值（`ResourceLibraryStatus` 3~7、`ResourceStatus` 不变、`ReviewTicketStatus` 等）。**没有删除任何既有列或表**。

**回退边界**
- 代码回退到旧版本：新表/新列不被旧代码读写，**无需回滚数据库**（旧代码忽略未知表/列）。
- 若必须删表：按上表逆序 `DROP TABLE`；`AppSchools` 的 3 列可直接删（旧代码未引用）。
- 唯一需要人工处理的是**枚举值**：旧代码读到 `ResourceLibraryStatus=3..7` 的库会显示"未知"，但不会崩溃；如需彻底还原，把这类库改回 `1`（Active）。

## 4. 应用回退步骤（推荐顺序）

1. **关开关**（第 2 节）→ 新入口报"未开通"，旧路径立即可用。
2. **回滚镜像**
   - 本地：`git checkout <上一个 tag>` + `./dev.sh restart api`
   - 生产：`docker tag <旧镜像> <当前 tag>` + `docker-compose up -d`（见 `etc/docker/DEPLOY-IKETONG.md`）
3. **观察**
   - `AppReviewTickets` 中仍为 `Pending` 的单据，回退后无人处理 → 建议回退前先在界面上清空或驳回
   - 已归档库（`status=2`）在旧代码里显示「已归档」，行为正常
4. **数据侧**：不需要 `Down()` 迁移；若企业/需求/任务数据需要清理，按业务确认后逐表删除（写操作前先备份）。

## 5. 验收清单（业务方逐项打勾）

### 5.1 教学资源库主线

| # | 场景 | 怎么验 | 通过标准 |
|---|------|--------|---------|
| V01 | 同模板建两个库 | `/admin/libraries` 新建时选同一模板 ×2 | 栏目/策略独立，内容不串库 |
| V02 | 校内库单级审核 | 建私有库 → 另一管理员在 `/admin/libraries/audits` 通过 | 通过前对教师/学生不可见；通过后「已发布」 |
| V03 | 共建库两级审核 | 建院校共建库 → 校审 → league-admin 终审 | 校审后「待联盟终审」且参建校不可见；终审后可见 |
| V04 | 自审拦截 | 提交人自己点「通过」 | 提示「不能审核自己提交的内容」 |
| V05 | 驳回→重提 | 驳回后点「重新提交」 | 轮次变 2，回到待审 |
| V06 | 改库审核 | 改名称/可见性 | 期间「变更审核中」按旧配置服务；通过后生效 |
| V07 | 删库归档 | 删除 → 审核通过 | 变「已归档」，**库行保留**，内容解绑 |
| V08 | 内容准入 | 教师共享草稿资源入库 | 生成「审核中」，通过后发布且内容同时变已审核 |
| V09 | 库内容只展示已发布 | 审核中时用另一账号看库内容 | 只有已发布可见；提交人可见自己的待审项 |
| V10 | 共建任务 | `/admin/libraries/tasks` 模板建任务 → 发布 → 协作校提交 → 主责校验收 | 进度 1/N；**验收后资源仍在待审**（验收≠发布） |
| V11 | 跨校引用 | `/teaching/shared-refs` 引用到本校课程 → 学生 `check-access` | 已选课可访问；撤销后立即不可访问 |
| V12 | 委外访问 | 学生访问本校私有库未分配资源（AI / 检索 / **文件 URL 直连**） | 三条路径都拿不到 |
| V12b | 文件 URL 绕过 | 学生拿私有库（未分配）资源 ID 直接请求 `/api/resource-file/{id}/preview|download` | **403**（不再因"已审核"而放行） |

## 6. 已知限制（不是 bug，已在文档标注）

| 项 | 说明 |
|----|------|
| 检索分页总数 | 结果按权限收口后重算 `TotalCount`，与索引命中数可能不一致（索引里仍有不可见文档）；彻底解决需索引层全字段裁剪 + 重灌 |
| 索引重灌 | 本环境演示资源文件无法解析（`文档解析未提取到任何页面`），重灌会失败；已提供 `SyncResourceMetadataAsync` 兜底（不依赖解析） |
| 库可见性/成员变更 | 索引同步只做了「内容发布」一个触发点；换库/改成员后需手动重灌 |
| 面试参与方 | 目前是面试官 + 学生 + 企业三方，未做多面试官列表 |
| 学生端播放器内联 | 「资源暂不可用」用的是引用管理页状态；播放器内联待做（`check-access` 接口已就绪） |
| 引用通知 | 建立/撤销/新版本发布暂无站内信或邮件（不影响权限，仅体验）——**经确认延后** |
| 章节编辑器/播放器内联 | 「暂不可用」目前体现在引用管理页，播放器内联占位——**经确认延后** |
| 前端自动化 | UI 层为人工清单（第 5 节）；API 层已脚本化 105 条 |
