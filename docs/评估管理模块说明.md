# 评估管理（教师填报与资料导出）

> 对应原型：`评估管理 · 老师创建与填报原型.html`
> 前端入口：`/assessment/manage`（菜单「评估管理」）
> 后端：`KnowledgeHub.Application/DoubleHigh/DoubleHighAppService.cs`（沿用双高评估模块 `DoubleHigh`）

## 一、整体流程（只到「教师提交」为止，不含审核 / 评分 / 公示）

页面顶部是三张可点击的**流程卡片**（① 创建项目 → ② 配置指标 → ③ 填报并提交），
点击直接跳到对应页签，**当前所在页签对应的卡片高亮**（标注「当前步骤」），提示用户当前处于流程哪一步。
「资料导出」不属于三步之一，此时三张卡片都不高亮。

「当前评估项目」是**跨页签的全局状态**（存在 `AssessmentContextService` 单例里）：
切页签会重建组件，所以不能只放在组件里，否则回到「评估项目」页签时选择会丢。

- 项目下拉选择器只在「评估项目」页签展示，它只是一个「选定当前项目」的过滤/选择作用，不会跳页签；
- 「填报指标 / 项目配置 / 资料导出」页签顶部显示当前项目名 + 「更换项目」链接（回到「评估项目」页签改）；
- 项目列表里点某一行的「配置 / 填报」会切换当前项目并直接进入该项目的对应页签。

| 步骤 | 说明 | 页面位置 | 后端接口 |
|------|------|----------|----------|
| ① 创建项目 | 选评估模板（课程建设 / 专业建设 / 教学团队），填名称、评估对象、截止日期 | 「评估项目」页签 → 新建评估项目 | `POST /api/app/double-high/from-template` |
| ② 配置指标 | 设置指标类型、数据来源、**权重**、**评分规则**、必备佐证、设置依据 | 「项目配置」页签 | `PUT /api/app/double-high/{id}` |
| ③ 开始填报 | 配置定稿并锁定，系统取数指标自动带出当前值 | 「项目配置」页签 → 开始填报 | `POST /api/app/double-high/{id}/start-filling` |
| ④ 填报 | 教师填数值 / 填说明 / 上传佐证文件 / 写自评说明 | 「填报指标」页签 | `POST /api/app/double-high/save-reporting`、`POST /api/app/double-high/evidence-file` |
| ⑤ 提交 | 全部指标完成才允许提交，提交后内容锁定 | 「填报指标」页签 → 提交填报 | `POST /api/app/double-high/{id}/submit` |
| ⑥ 导出 | 导出评估数据 + 佐证文件原件，形成 zip 资料包 | 「资料导出」页签 | `POST /api/app/double-high/export-package/{id}`、`POST /api/app/double-high/export-all-package` |

## 一之二、评估对象（自动取值的上下文范围）

评估对象不只是"填个名字"，它决定了「系统取数」指标的**数据范围**：

| 对象类型 | 取值范围 | 自动取数口径 |
|---|---|---|
| `ResourceLibrary` 教学资源库 | 该库 | 库内课程 / 资源（含共建学校内容，不受租户过滤限制） |
| `Major` 专业 | 该专业 | 主专业字段 + 课程—专业关联表里的课程，及其资源、选课、完成率、就业率 |
| `Course` 课程 | 该课程 | 该课程的资源、选课人次、完成率（该课程学生） |
| `Manual` 手动填写 | 逐指标确认 | 默认全校；老师可为每个系统取数指标单独指定 资源库 / 专业 / 课程 / 全校 |

实现要点：

- 项目字段：`ObjectType` / `ObjectId` / `ObjectName`（名称快照，对象被删也能看出评估的是谁）。
- 指标字段：`ScopeType` / `ScopeId` / `ScopeName`（为空 = 随项目对象）；
  `DoubleHighScopeResolver.Resolve(project, indicator)` 决定实际范围，
  `GetCourseIdsAsync / GetResourceIdsAsync / GetStudentIdsAsync` 把范围翻译成具体 Id 集合。
- **范围查询必须关闭租户过滤器**：宿主管理员（TenantId = null）和共建库都要能取到租户数据。
- 对象候选项接口：`GET /api/app/double-high/object-options?objectType=1|2|3&filter=`（同样关闭租户过滤）。
- 前端：新建项目弹窗选「对象类型 + 具体对象」；「项目配置」页可改对象，
  指标表有「取值范围」列（随项目对象 / 全校不限 / 资源库 / 专业 / 课程）。
  手填对象且系统取数指标还是「随项目对象」时，配置页会提示需要确认范围。

## 二、指标模型（配置项目时就要设好权重与评分规则）

| 字段 | 枚举 | 说明 |
|------|------|------|
| `IndicatorType` | `Auto` 系统取数 / `Number` 填写数值 / `Text` 填写说明 / `EvidenceOnly` 仅佐证 | 决定填报页面对该指标的操作方式 |
| `ScoringRule` | `Proportional` 比例制 / `Threshold` 达标制 / `Direct` 直接计分 / `None` 不计分 | 决定完成度如何折算得分 |
| `Weight` | 0~1 小数，项目内合计 ≤ 1 | **沿用原有权重算法**（权重 × 完成度加权求和 / 权重合计） |
| `RequiredEvidences` | 字符串数组 | 必备佐证清单，每一项都至少要上传一个文件，该指标才算完成 |
| `Basis` | 文本 | 设置依据（手写文本，如国家基本框架观测点） |
| `BasisDocumentId` | Guid? | 设置依据也可直接**引用项目依据文件**（见下），填了它就以文件为准 |
| `TargetValue` | 数值 | 比例制时是上限、达标制时是下限（实际值超过目标值算达标） |

完成度折算规则（后端 `CalculateIndicatorProgress`）：

- 比例制：`min(100, 实际值 / 目标值 × 100)`
- 达标制：`实际值 ≥ 目标值 → 100`，否则 `0`
- 直接计分：教师填的值本身（0~100）
- 不计分：恒为 0（只展示，不参与加权总分）

项目两个口径：

- **填报进度** = 已完成指标数 / 指标总数（含必备佐证是否齐全）
- **加权总分** = Σ(权重 × 完成度) / Σ(参与计分的权重)，0~100
- 历史字段 `completionRate` 保留原算法（按权重加权的完成度，未归一化到计分权重）

## 二之二、项目依据文件 + 佐证材料

**项目依据文件**（政策文件、评估办法、通知等，可上传多个）：

- 实体 `DoubleHighProjectDocument`（表 `AppDoubleHighProjectDocuments`），上传走
  `POST /api/app/double-high/project-document/{projectId}`（multipart：file + title）。
- 文件存储复用 `DoubleHighEvidenceFileStore`（OSS 优先，本地回退）。
- 指标的「设置依据」有三种形态：不填 / 手写文本 / 引用项目依据文件；
  引用后填报页显示「📎 文件名（点击查看）」，OSS 直链直接打开，本地文件走下载接口。
- 删除依据文件时，引用它的指标依据会置空（不留下悬空引用）。

**佐证材料**：

- 「必备佐证」按配置的槽位分组上传；**没有配置必备佐证的指标**（如新增指标、仅佐证指标）
  也提供「其他佐证材料」上传区，老师可直接传文件。
- 项目列表页有「佐证材料」列，显示该项目已上传的佐证份数。

## 四、资料包（zip）结构

```
评估资料包/                     ← 「导出全部项目」时的根目录
  00_导出总览.md                ← 所有项目一览表
  <项目名>/
    00_项目说明.md              ← 对象 / 模板 / 截止 / 填报人 / 阶段 / 进度 / 总分 / 流程说明
    01_指标体系.csv            ← 编号 / 名称 / 类型 / 单位 / 来源 / 权重 / 评分规则 / 目标值 / 必备佐证 / 依据
    02_填报内容.csv            ← 系统取数 / 填报值 / 填报说明 / 自评说明 / 佐证数 / 完成状态
    03_佐证材料清单.csv        ← 编号 / 指标 / 佐证名称 / 文件名 / 大小 / 包内路径
    依据文件/                  ← 项目依据文件原件（政策文件等），1_xxx.pdf
    04_评分汇总.csv            ← 权重 / 完成度 / 加权得分 / 评分规则 / 依据
    佐证材料/
      I05_就业率/就业质量年度报告/1_就业质量年度报告.txt
```

CSV 带 UTF-8 BOM，Excel 直接双击不乱码。佐证文件原件从 OSS（或本地磁盘回退）读取后打进 zip；
读不到原件时写一个 `.说明.txt` 占位，保留清单与目录结构，不会静默丢文件。

佐证文件存储：`DoubleHighEvidenceFileStore`

- `oss:{objectKey}` —— 阿里云 OSS（优先，复用管理页维护的租户级 AK/SK/Bucket）
- `local:{relativePath}` —— 本地 `App_Data/assessment-evidence`（未配置 OSS 时回退）

## 七、注意事项

1. **保存项目配置不会清空已填报的数据**：指标按「编码」原地更新，编码消失的指标才连带删除其填报值与佐证
   （历史实现是「全删重建」，改一下权重就会把填报内容清空）。
2. **提交后锁定**：`SaveReportingAsync` / `AddEvidenceFileAsync` 对 `Submitted` / `Closed` 状态的项目会拒绝写入。
3. **系统取数指标不可手工修改**：`SaveReportingAsync` 对 `IndicatorType = Auto` 直接报错；需要刷新就重新「开始填报」或调用采集接口。
4. **达标制指标允许超过目标值**：「实际值 ≤ 目标值」的旧校验只对比例制生效。
5. 旧的「双高评估项目 / 详情 / 报表中心」页面仍然可用（路由保留），但菜单入口已改为新的「评估管理」。
