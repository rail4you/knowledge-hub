## 二、逐场景语音脚本（旁白原文）

> 语音合成：MiniMax `speech-2.8-hd`，音色 `Chinese (Mandarin)_Reliable_Executive`，语速 0.9。
> 字幕来自 TTS 返回的 SRT（逐句精确时间轴），因此字幕与语音严格对齐。

### 场景 1 · 片头（29.6 秒）

> 欢迎观看特殊教育课程教学资源平台的功能演示。本视频全部内容均取自生产环境的真实操作录屏，登录、点击、提交、审核全部现场发生，不做任何后期拼接。演示覆盖四组核心能力：课程资源管理、名师工作室、互动课堂课表，以及教师教研白板。下面按顺序逐一呈现。

### 场景 2 · 平台总览（47.2 秒）

> 首先是平台总览。登录之后进入的是统一门户首页，顶部提供综合搜索，页面按模块聚合资源推荐、课程学习与 AI 助手入口；左侧导航则根据当前账号的角色自动呈现可访问的功能模块——教师看到的是课程内容、智学分析、教研协同等教学入口，学生看到的则是我的课程、我的作业与学习成长。平台的治理底座是同一个资源中心：所有教学资源都沉淀在这里，由统一的分类体系、审核流程与权限策略管理。下面通过四组功能，逐一说明这套底座是如何运转的。

### 场景 3 · 课程资源管理（后台建资源，63.0 秒）

> 第一组，课程资源管理。先看后台的建资源流程。在资源中心点击新建资源，表单中的「所属模块」下拉框预置了十个栏目：课程资源、职业教育、融合教育、政策经验、大讲堂、课标教材、教具辅具、家长课堂、学生成长，以及专题教育。这十个栏目直接复用平台既有的资源分类树，不需要另建一套体系。这里选择「教具辅具」，然后填写资源名称、资源类型与内容简介，并上传对应的教学文件——画面中可以看到上传进度条实时推进。提交之后，这条资源立刻进入「待审核」状态，由资源审核中心统一处理，审核人可以是院校管理员或平台管理员，审核结果对所有前台用户可见。

### 场景 4 · 课程资源管理（前台筛选与播放，56.7 秒）

> 接着看前台的使用。资源中心的筛选栏支持按模块、专业、状态等属性组合筛选：先选择「政策经验」，列表立即收窄为三条政策类资源；再切换到「课标教材」，列表变为两条，其中一条是特教课堂教学示范视频。点开这条资源的详情页，页面给出资源名称、所属模块、类型、上传者以及审核状态，并内嵌播放器。点击播放，视频在浏览器中真实加载出画面与声音，前台体验与本地播放完全一致。审核机制保证了只有通过审核的资源才会对外可见，学生的观看、收藏与下载都建立在审核结果之上，未通过的资源对非创建者不可见。

### 场景 5 · 名师工作室（成员上传，52.2 秒）

> 第二组，名师工作室。工作室是学校层面的教师协同空间，列表中可以看到工作室名称、领衔人、成员数量，以及已发布和待审核的资料数量。点进工作室详情，页面上方是领衔人与成员信息，下方是资料列表。现在以成员身份进入，点击「上传资料」，弹窗可以直接从自己的课程资源中选取文件——这意味着工作室资料复用的是平台已经成熟的资源上传、分片传输与媒体处理能力，不需要重复上传，也避免同一份文件在系统里存两份。再补充标题与说明后提交，这条资料立即标记为「待审核」，等待领衔人处理。

### 场景 6 · 名师工作室（领衔人审核发布，59.8 秒）

> 同一时刻切换到领衔人账号。工作室头部提示有一份待审资料，资料卡片上出现「通过并发布」与「驳回」两个操作。点击通过并发布，卡片标签由「待审核」变为「已发布」，头部计数同步更新，已发布数量加一、待审数量归零。再切回普通用户账号刷新页面，刚发布的资料已经出现在「已发布资料」列表中，可以直接预览与下载。同一条资料、两个不同账号，完整跑通了「上传—审核—发布—可见」的闭环，而领衔人就是这条链路上真正的审核人。此外，当提交人与审核人是同一人时，系统会跳过审核直接发布，避免自审流程阻塞教学使用。

### 场景 7 · 互动课堂课表（58.3 秒）

> 第三组，互动课堂课表。课表并不是另建一套排课系统，而是复用课堂智能体任务的既有数据：每个任务按布置日和截止日两个时间点落位，因此在课表上形成课节，零新增数据表。默认进入周视图，七列对应周一到周日，课程块分布在各自的时间行上。把鼠标悬浮在任意课程块上，浮层完整显示课程名称、日期、时间段和学校四项信息，正好对应采购需求中点名的悬浮内容。切换到日视图，课程按小时时间轴展开；切换到月视图，以日历网格呈现当月的课节分布，顶部还可以按课程进一步筛选。课表因此既是教学排期的总览，也是课堂任务的执行看板。

### 场景 8 · 教师教研白板（创建与邀请，50.2 秒）

> 第四组，教师教研白板。教师 A 进入教研白板列表，新建一个白板，填写主题「《春》第二课时研讨」以及学科年级，创建后直接进入画布房间，右上角显示协同状态与在线成员。点击「邀请教师共创」，弹窗列出本校的教师，选择同事后发送邀请。此时切到教师 B 的账号，刷新白板列表，刚才的白板已经出现，并带有「被邀请」标记；B 打开之后，两个人的在线头像同时显示在右上角，成员关系也写入白板的成员列表中，后续权限与访问范围都以此为准。

### 场景 9 · 教师教研白板（双人实时共创，68.5 秒）

> 接下来是共创过程。画面左右两侧是两个不同账号的浏览器窗口，指向同一个白板。教师 A 添加一段教学目标文本，B 的画布立即同步出现同样内容，不需要刷新；A 在右侧面板修改文字表述，B 端的文本同步变化；拖动文本块，两个窗口中的位置同步移动。B 新增的便签「建议增加朗读环节」，在 A 端实时出现，并带上提交人署名；鼠标移动时，屏幕上还会出现对方的彩色光标与姓名标签，直观呈现协同过程。素材可以直接从课程资源中选取插入，无需另行上传。保存后内容持久化在服务端，双方刷新后仍然一致。整个协同依托 WebSocket 长连接实现，是真正的多人实时共创，而不是轮流编辑后互相刷新。

### 场景 10 · 收尾（36.3 秒）

> 以上就是本次演示覆盖的四组能力：课程资源管理完成资源的模块化沉淀与前台消费；名师工作室跑通领衔人审核发布链路；互动课堂课表以三种视图呈现教学排期；教师教研白板实现多人实时共创。四组能力共用同一套资源治理、审核流程与权限体系，因此平台既能承载单校教学场景，也能支撑校际共建与统一门户。谢谢观看。

## 四、重新生成视频

```bash
cd scripts/demo/video

# 1) 旁白合成（MiniMax TTS，自动产出 mp3 + 精确时间轴 srt）
./tts.sh

# 2) 生产环境录屏（Playwright 驱动真实浏览器，逐场景录制）
./record-all.sh s01-overview s02-resource-create s03-resource-browse \
                s04-studio-upload s05-studio-review s06-timetable \
                s07-whiteboard-create s08-whiteboard-collab s09-outro

# 3) 合成：标题卡 + 录屏 + 字幕 + 旁白 → 单场景 mp4 → 合并成片
python3 build.py
```

产物：

| 路径 | 内容 |
|---|---|
| `out/final/特殊教育课程教学资源平台-功能演示.mp4` | 成片（8:42，23 MB） |
| `out/final/<scene>.mp4` | 单场景片段（便于按组分包） |
| `out/tts/*.mp3` / `*.srt` | 旁白音频与字幕时间轴 |
| `out/raw/<scene>.webm` | 原始录屏 |

调参位置：

- 文案/标题卡文字：`voiceover.json`（`scenes[].voice` = 旁白，`group/title/subtitle` = 标题卡）
- 标题卡样式：`render-text.mjs`；字幕样式：`render-subs.mjs`
- 时长对齐策略：`build.py`（录屏比旁白短 → 按比例放慢到 0.6 倍速下限 + 末帧补足；长 → 至多 1.25 倍速并裁尾）
