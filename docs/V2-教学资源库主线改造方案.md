## 3. 目标模型

### 3.1 统一审核内核（ReviewTicket）

所有"要审核的东西"挂同一聚合，历史只追加：

```
ReviewTicket                        审核单（聚合根，IHasConcurrencyStamp）
  TargetType      Library | LibraryPublication | BuildTaskDelivery
                  | EnterpriseProfile | EmploymentJob | CooperationDemand
  TargetId        目标实体 Id
  ActionType      Create | Update | Delete | Admit | Publish | Certify
  LibraryId?      库维度（跨校场景必填，决定终审方）
  ContentTenantId?  内容归属学校（决定初审方）
  PayloadJson     变更快照（提交什么，通过后按快照应用）
  PayloadHash     冲突检测（同目标同内容重复提交 → 幂等命中）
  Stage           School | League            ← 当前阶段
  RoundNo         轮次（驳回后重提 +1）
  Status          Pending | Approved | Rejected | Cancelled
  SubmittedBy / SubmittedAt / ReviewerId / ReviewedAt / Reason

ReviewAction                        审核动作（只追加，不更新不删除）
  TicketId, Stage, ActorId, ActorTenantId,
  Decision(Approved/Rejected/Returned), Reason, SnapshotJson, CreationTime
```

**事务内硬校验**
1. `SubmittedBy != CurrentUser.Id`（回避本人）；
2. 同 ticket 的 `League` 审核人 ≠ `School` 审核人；
3. `ConcurrencyStamp` 不符 → 409（不静默覆盖）；
4. 状态/轮次不符 → 业务异常（文档 18「审核状态冲突」）；
5. 审批 + `ReviewAction` + 事件记录同事务；通知失败由事件重试，不回滚审批。

**幂等**：`(TargetType, TargetId, ActionType, PayloadHash, Status=Pending)` 唯一约束 → 重复提交返回首次结果。

### 3.2 阶段规则（C1 + C4）

| 对象 | 初审（School） | 终审（League） |
|------|---------------|---------------|
| 校内私有/公开库：建库、改库、删库 | 本校 `SchoolAdmin` | — （单级，C1） |
| 院校共建库：建库、改库、删库、成员变更 | 主建校 `SchoolAdmin` | `LeagueAdmin` |
| 内容 + 库准入（草稿内容入库，合并流程 C2） | 内容归属校 `SchoolAdmin` | 共建库：`LeagueAdmin`；校内库：— |
| 库准入（已发布内容入新库） | 内容归属校 `SchoolAdmin` | 共建库：`LeagueAdmin`；校内库：— |
| 企业档案认证 | 入驻学校 `SchoolAdmin` | `LeagueAdmin` |
| 企业贡献（案例入库） | 合作校 `SchoolAdmin`（无合作校时平台预指派） | `LeagueAdmin` |
| 共建任务交付验收 | 任务主责校 `SchoolAdmin` 或库级 `Manager` | — |

> 库级职责（文档 6.3 的"库负责人"）由 `LibraryRoleAssignment`（Manager / Contributor / Auditor）表达，**不建系统角色**（C4、D-A1）。

### 3.3 状态机（只追加枚举值）

**ResourceLibrary.Status**（0/1/2 不动）

```
0 Draft
3 PendingReview        建库审核中（对成员校/学生不可见）
4 PendingLeagueReview  院校初审通过，等联盟终审（仅共建库）
5 Rejected             驳回（改后重提，RoundNo+1）
6 ChangePending        变更审核中（库仍按旧配置服务，变更存 PayloadJson）
7 DeletePending        删除审核中（库仍正常服务）
1 Active
2 Archived             删除/停用审核通过后进入（C8：不硬删，审核数据保留）
```

**ResourceStatus**（0~5 不动，D-A2 映射）：`Draft(0) → PendingReview(1)校审 → SchoolApproved(2)待终审 → LeagueApproved(3)发布`，`Rejected(4)`、`Hidden(5)` 保留。

**ResourcePublication**（库维度准入，与内容审核正交但可合并流程）

```
Draft → PendingReview → Published / Rejected / Withdrawn
```
- 内容未发布（Draft/Rejected）+ 入库 → **一条流程**：校审同时判内容与准入 → 共建库再终审 → 内容 `LeagueApproved` 且 publication `Published`（C2）；
- 内容已发布 + 入新库 → **单级准入审核**（校内库本校管理员 / 共建库联盟终审）；
- 库内内容查询默认只取 `Published`；提交人、审核人可见自己的待审项。

**BuildTask.Status**：`Draft → Published → InProgress → Submitted → Accepted / Returned → Closed`。

### 3.4 共建任务与模板

```
ResourceLibraryTemplate      Code, Version, Name, ConfigJson, Status
  ConfigJson: { modules[], catalogSkeleton[], requiredFields[],
                reviewStages[], defaultPolicy{}, taskTemplateCodes[] }
ResourceLibrary              + TemplateId, TemplateVersion, ConfigSnapshotJson, ConcurrencyStamp

BuildTaskTemplate            LibraryId?, Code, Name, CourseId?, Status
BuildTaskTemplateItem        TemplateId, ItemName, ResourceType, RequiredCount, Acceptance

BuildTask                    LibraryId, CatalogNodeId?, TemplateId?,
                             OwnerSchoolId, OwnerUserId, ReviewerUserId?,
                             DueAt, Requirements, Status
BuildTaskCollaborator        TaskId, SchoolId, UserId?, Capability(Contribute/View)
BuildTaskItem                TaskId, ItemName, ResourceType, RequiredCount, AcceptedCount
BuildTaskDelivery            TaskItemId, PublicationId, ResourceId,
                             SubmittedBy, Status(Submitted/Accepted/Returned), Comment
```

进度 = `AcceptedCount / RequiredCount`；同一 `PublicationId` 不得重复计入同一任务的多个同类项（文档 4.2）。**任务验收 ≠ 资源审核**（两次动作、两条历史）。

### 3.5 跨校引用（P4，C3）

```
CourseSharedRef
  TargetTenantId      接收校
  CourseId / ChapterId / SectionId
  LibraryId           来源库
  ContentType         Resource | Course
  ContentId / ContentVersionId（固定版本）
  SourceTenantId
  Status              Pending | Active | Revoked
  CreatedBy / CreationTime / RevokedBy / RevokedReason
```

- 学生可见 = `Active` + 学生在目标课程的 `StudentCourse` 关系内；
- 下架/撤权 → `Revoked`，课程页显示"资源暂不可用 + 替换入口"（不静默消失）；
- 升级 = 新增一条 ref 指向新版本，旧 ref 保持（不覆盖历史学习）；
- 鉴权统一走 3.6，不在课程表写文件地址。

### 3.6 统一资源访问判定（D5）

`IResourceAccessChecker`（Application 层，无状态可缓存）：

```
Task<bool> CanAccessAsync(Guid resourceId, ResourceAccessIntent intent);
// Preview | Download | Study | AiIndex | SearchHit | AssignToLibrary
Task<IReadOnlyCollection<Guid>> GetAccessibleResourceIdsAsync(ResourceAccessScope scope);
```

判定链（全部通过）：账号有效 → 资源已审核 → 内容归属（本校 / 共建库成员校且已 Published）→ 库可见性（库 `Active` + 私有库需被分配）→ 课程引用（学生路径）→ 下载权限 `Resources.Download` 与预览分离。

替换点：`ChatAppService`、`MeiliSearchService`（索引字段 + 查询 filter）、`ResourceFileController`、`ResourceAppService.DownloadAsync`、缩略图/摘要生成。

### 3.7 单位有效期（C6，新增，本期）

与既有 `AccountValidity`（用户级权限熔断）**并存**，不是替代：

```
School                + ValidFrom, ValidTo, ValidityStatus   （1:1 租户，全局实体）
EnterpriseProfile     + ValidFrom, ValidTo                   （企业主体，3.8）
```

- **门禁语义**：到期后 ①只读可用（已发布内容按原权限展示）；②**禁止写操作**（新建/编辑/删除/上传/导入/发布/审核/授权/投递）；
- **实现**：`IOrganizationValidityChecker`（Domain 服务，按 `CurrentTenant` 查 `School.ValidTo`；企业用户追加查 `EnterpriseProfile.ValidTo`）+ `OrganizationValidityFilter`（`HttpApi.Host` 全局 `IAsyncActionFilter`，按 HTTP 方法判定，路径白名单：登录/注册/本地化/health/账号自助）+ `[AllowExpiredOrganization]` 逃生属性；
- **异步任务**：Hangfire job 执行时**重新校验**（文档 7.3 "接口、队列任务、上传回调都须复核"）；
- **到期时间解释**：截止日按北京时间 23:59:59；**续期只恢复原有授权，不扩大**；
- 主建单位到期 → 依赖主建审核的任务暂停并通知管理员；参建单位到期只冻结自身维护范围。

## 5. 分期与任务分解

|------|------|------|
| P0 | 基线核对 + 开关骨架 | 1–2 |
| **P1** | 审核内核 + 资源库建/改/删（归档）审核 | 8–11 |
| **P2** | 库准入审核（合并内容审核）+ 联盟跨校终审 + 可见性口径统一 | 7–9 |

### P0 基线核对与开关（1–2 人日）
- 产出《能力差距表》：认证、租户解析（`SchoolDomain`）、文件链路、索引链路、统计口径。
- 功能开关：`LibraryReview` / `BuildTask` / `CrossSchoolRef` / `EnterpriseWorkspace` / `OrganizationValidity`（默认关）。
- 固化冒烟脚本（curl + Angular build + `dotnet build`）。

## 7. 主要风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| ABP 租户过滤器误用 | 跨校静默读不到（`Members` 空集合） | 跨租户查询一律 `Include` + `Disable<IMultiTenant>()`，审核/测试覆盖 |
| 枚举追加影响 `status=3` 过滤与索引 | 学生看不到/看到不该看 | 只追加不改旧值；索引与查询在同一迁移内同步 |
| `GrantAllPoliciesMiddleware` 注入 | 新权限误注入导致前端有按钮后端 403 | 高权限不入注入列表，靠 `RolePermissionSeeder` 真实授权 |
| 代理全量重生成覆盖手改 | 前端异常 | 生成后按 git diff 恢复手改项 |
| 双写期旧路径绕过审核 | 审核形同虚设 | 开关关闭期保持旧行为；启用后**删除**旧的直接写入分支 |
| 单位有效期门禁过严 | 正常用户被拦 | 白名单 + `[AllowExpiredOrganization]` + 灰度按租户开；先只拦"发布/审核/授权/上传"等高价值写操作 |
| 审核积压 | 上线初期阻塞 | 待审列表 + 超时提醒 + 同阶段批量审核 |
