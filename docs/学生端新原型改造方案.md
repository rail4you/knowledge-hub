| 维度 | 结论 |

## 1. 目标与范围

**目标**：以新原型为参考方案，重构学生端前端（以学生端为主），尽可能连通现有数据架构；原型里的 mock 数据全部替换为真实 API；无法替换的部分汇总待评审。

**范围内**
- 学生端页面（`/student/**`）的信息架构、交互流、视觉语言重构
- 原型 mock 数据 → 真实 API 的逐项替换
- 为支撑学生端所需的**最小**后端补充
- 前端公共基建整改（令牌、导航、service 双轨、分页）

**范围外（需你确认是否另立批次）**
- 教师端 / 管理端页面的原型化改造（原型 101 视图里学生只占 54 个）
- 真实 OCR / 音视频 / AI 推理 / 电子签章（原型自己就标注为占位）
- 产教合作平台闭环（需 3–5 个新实体）
- 共建共享资源库的「模板快照 + 版本引用」体系

## 3. 改造策略

### 3.1 三层改造

```
L1 基建层  令牌统一 / 布局与导航 / 共享组件 / service 双轨收敛 / 分页 / 权限守卫
   ↓
L2 页面层  现有 36 路由 → 按原型信息架构与视觉语言重做，数据全部接真实 API
   ↓
L3 领域层  原型新增能力（教学班 / 作业闭环 / 成果档案 / 学习路径 / 信任中心 …）
```

L1+L2 **不需要新建任何后端领域**，可在方案通过后立刻开工。L3 需要第 7 节的模型决策。

### 3.2 为什么不全量重写

- 现有学生端 36 条路由背后是**已验证的真实数据链路**（实训提交、简历投递、微专业发证、试卷校对都已跑通），重写会连带丢掉这些已验证行为。
- 原型有 4 处明确的**信息架构缺陷**（双简历实现、3 个门禁缺口、6 套重复导航条样式、`learning-entry` 语义错位），照抄会引入新债。
- 结论：**以现网路由为骨架，以原型为视觉与交互规格**，原型有而现网没有的能力才新增。

### 4.1 令牌统一（对应 D4）

现网 3 处维护同一主色（`styles/_design-tokens.scss:27`、`student/styles/_student-design.scss:7`、`styles.scss:77`），原型又引入第 4 套。收敛为**单一来源**：

### 4.2 组件层（原型值得搬的 6 个 + 必须补的 5 个）

9. `ErrorState` — 带重试
10. `Pagination` — 统一服务端分页（替换现网 6 处客户端切片）
11. `FormFieldError` — 字段级校验

### 4.3 保留的原型交互约定
