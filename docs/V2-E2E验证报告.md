# V2.0 P1–P4 端到端验证报告

> 验证对象：教学资源库主线（建库 → 审核 → 内容准入 → 共建任务 → 跨校引用）在 P1~P4 的实现。
> 验证方式：可重复执行脚本 `scripts/test/v2-e2e.sh`（curl + psql 断言），覆盖 **3 条主流程 + 1 组权限矩阵**。
> 最近一次执行：**105 通过 / 0 失败 / 0 跳过**（P1~P5，8 条流程 A~H）。
> 账号见 `docs/V2-测试账号与环境.md`。

---

## 1. 如何执行

```bash
./dev.sh start                       # 或至少 start api
./scripts/test/v2-e2e.sh             # 全程约 60~90 秒
```

脚本行为约定：

- **自带前置**：为 `qidi` / `guozhou` 打开 `LibraryReview` / `BuildTask` / `CrossSchoolRef` 三个开关（可反复执行）
- **自带数据自举**：自动创建并发布两门专用课程（`E2E-课程-已选` / `E2E-课程-未选`）与 guozhou 的一门课程，并把 zmq 选进「已选」课；
  自动挑选「草稿且未入库」的资源与已有任务模板
- **自带清理**：结束时删除本次生成的库 / 任务 / 交付 / 引用 / 审核单，**可重复跑**
- 退出码：全通过为 0，有失败为 1（可直接接入 CI）

## 3. 本轮 E2E 发现并修复的缺陷（4 个真实产品缺陷）

| # | 缺陷 | 影响面 | 根因 | 修复 |
|---|------|--------|------|------|
| 1 | **交付记录归属写错租户** | 主责校验收后进度恒为 0，`review-delivery` 查不到记录 | `BuildTaskDelivery.TenantId` 记成「提交方学校」，而任务/库归属主责校 | 改为 `task.TenantId ?? task.OwnerSchoolId`；DTO 组装时跨租户读 |
| 2 | **协作校看不到共建任务** | 「我的共建任务」恒为空，协作校无法参与 | `GetTasksAsync` 受租户过滤器限制（任务归属主责校） | 整个查询（含协作关系匹配）放进 `Disable<IMultiTenant>()` 作用域，再用「本校是否主责/协作」收敛 |
| 3 | **待联盟终审状态从不落库** | 校审通过后库仍显示「待院校审核」，UI 无法区分阶段 | 枚举有 `PendingLeagueReview`，但代码从不设置 | 新增可选接口 `IReviewStageHandler.OnStageAdvancedAsync`，在阶段推进（未终审）时回调，库处理器置 `status=4` |
| 4 | **协作校提交受本校开关限制** | 协作校未单独开通 `BuildTask` 时无法提交 | `EnsureFeatureAsync` 用「提交方租户」判定 | 提交时改按「库归属学校」判定（`EnsureFeatureForLibraryAsync`） |

> P5 阶段（Flow G）另发现 2 个缺陷：
> 1. **EnterpriseUser 缺 `ResourceLibraries.Build` 权限** → 企业贡献在授权层就 403，业务门禁根本走不到；
>    已补授权（真正的写入门禁由库访问规则 + 企业认证状态把关）。
> 2. **未认证企业的报错是笼统的"无权"** → 改为明确原因「企业尚未通过认证或已过有效期…」。
>
> P5 阶段（Flow F）发现 3 个缺陷：
> 1. **需求大厅受租户过滤器限制** —— 外校看不到已发布的公开需求（跨校场景整个功能不可用）；
>    修复：大厅/响应/项目查询统一 `Disable<IMultiTenant>()` + 按 `Scope`（仅入驻校/联盟内/公开）收敛。
> 2. **项目台账管理员看不到自己企业的项目** —— 项目 `TenantId` 记的是「合作学校」，
>    入驻企业侧按 `SchoolTenantId == 我的租户` 过滤必空；修复：管理员查询 OR 上「本校企参与」。
> 3. **推进阶段后返回的里程碑数为 0** —— 未带 `WithDetails` 加载；修复：改按 details 查询。
>
> 另有 1 个缺陷：
> **同一用户属于多家企业时，「我的企业」稳定返回最早的一家**（`FirstOrDefault`），
> 导致新建企业后页面仍显示旧企业。已改为「主联系人优先 + 最近创建」，并补 `GET /api/app/enterprise/{id}` 精确查询。
>
> 另有 2 处**设计确认**（不是缺陷）：
> - 校内库（私有/公开）教师**必须被显式分配**才可见 —— 脚本 A5a 先分配再断言
> - 参建校教师**不默认可见**共建库，需主建校分配 —— 断言 B6b 固化该行为

### 脚本自身的 3 个 bug（已修，供参考）

1. `jg()` 误写成读第二个参数，导致所有 JSON 断言返回空
2. `api()` 被塞入 `-o /dev/null -w '%{http_code}'`，body 位置错乱 → 新增 `api_code()`
3. 变量后紧跟全角括号时 bash 把括号当变量名一部分 → 统一 `${VAR}`
