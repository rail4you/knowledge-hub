# 资源预览架构

> 本文档描述资源在线预览的完整链路与设计原则。核心思想：**转换只在资源入库时发生一次，预览端只读取已生成的产物，不再触发任何转换或重试。**

---

## 1. 一句话原理

资源上传/换版本后，后台媒体流水线自动生成**缩略图**和 **Office 预览 PDF**，并登记为 `ResourceArtifact` 生成物；
前端预览时直接读取该生成物（PDF 通过 pdfjs 的 Range 请求流式加载），**未转换完成的文档只显示 loading，等后端处理即可，前端不触发转换**。

---

## 2. 唯一流程

```
资源上传 / 换版本 / 回滚
        │
        ▼
ResourceMediaJobManager.EnqueueAsync()          ← 创建 ResourceMediaJob（Pending）
        │  (Hangfire "media" 队列，事务提交后入队)
        ▼
ResourceMediaProcessingJob.ExecuteAsync()       ← 状态 Running，边执行边写进度
        │
        ▼
ResourceMediaProcessor.ProcessAsync()
   ├─ Office 文档(ppt/pptx/doc/docx/xls/xlsx)
   │     └─ ConvertToPdfAsync() → converted/{resourceId}.pdf
   │        + ResourceArtifact(PreviewPdf, "full")   ← 「预览完成」
   │        + ResourceArtifact(Thumbnail, "w400")    ← 由 PDF 首页光栅化
   ├─ PDF
   │     └─ ResourceArtifact(Thumbnail, "w400")
   ├─ 图片 / 视频
   │     └─ ResourceArtifact(Thumbnail, "w400")
   └─ 其它（仅正文等，无文件）
         └─ MediaStatus = Ready（无需处理）
        │
        ▼
Resource.MediaStatus = Ready / PartialFailed / Failed
ResourceMediaJob.Status = Completed / PartialFailed / Failed（写入进度与错误信息）
```

预览端（`ResourceFileController`）：

| 端点 | 作用 |
|------|------|
| `GET /api/resource-file/{id}/preview-pdf-info` | 只读状态：`{ready, tooLarge}`。`ready=true` 当且仅当存在 **Ready 的 PreviewPdf 生成物且文件在盘**。**不触发转换**。 |
| `GET /api/resource-file/{id}/preview-pdf` | 返回生成物 PDF（`PhysicalFile` + `enableRangeProcessing`）。未就绪返回 `409`。**不做同步转换兜底**。 |
| `GET /api/resource-file/{id}/thumbnail?w=400` | 优先返回媒体流水线登记的缩略图生成物；文档类按宽度从预览 PDF 首页光栅化。 |
| `GET /api/resource-file/{id}/preview` | 返回**原始源文件**（PDF/图片/视频/音频/文本直出，支持 Range）。 |
| `GET /api/resource-file/{id}/download` | 下载原文件（带权限与「不允许下载」校验）。 |

## 3. 前端预览

组件：`angular/src/app/shared/preview/`

```
file-preview.component        预览弹窗（类型判定 / 大小降级 / 分发）
  ├─ pdf-viewer.component     统一 PDF 渲染器（pdfjs-dist）
  ├─ media-viewer.component   图片 / 视频 / 音频
  └─ text-viewer.component    纯文本
```

### 3.1 类型分发（`file-preview.component.ts`）

| 类型 | 预览方式 |
|------|---------|
| `pdf` | `pdf-viewer [previewUrl=/preview]`，直接流式加载源 PDF |
| **Office PPT/DOC**（ppt/pptx/doc/docx） | `pdf-viewer [resourceId]`，统一走后端转换的 PDF |
| **Excel**（xls/xlsx） | `excel-viewer [data]`，SheetJS 客户端解析（表格观感优于 PDF） |
| image / video / audio | `media-viewer`（图片走 ArrayBuffer，音视频走 streamUrl） |
| text（含 csv/tsv/json/xml 等） | `text-viewer`（ArrayBuffer） |
| 其它 | 降级页：提示不支持 + 下载 |

> `.docx` 不再用 mammoth 客户端解析；PPT/DOC 与 PPT 一样由媒体流水线转成 PDF 统一预览。**Excel 单独保留 SheetJS 客户端渲染**——表格类内容用 PDF 预览观感较差。

### 3.2 Office 预览时序（`pdf-viewer.component.ts` → `loadOfficePreview`）

```
1. 轮询 GET /preview-pdf-info  （每秒一次，最多 600 次 ≈ 10 分钟）
     ├─ ready=true   → 进入第 2 步
     └─ tooLarge=true → 显示「文件过大，请下载查看」
2. GET /preview-pdf              （pdfjs Range 流式加载整份 PDF）
3. 渲染第 1 页 → 展示；预渲染第 2 页；其余页翻页时按需渲染
```

**关键约束（请勿破坏）**：

- 前端**只读取**转换状态，**绝不触发**转换、入队、同步转换或额外重试。
- 若后端转换失败或尚未完成，前端保持 loading / 超时提示，等待后端恢复即可。
- **不要**在打开预览时下载整份 PDF 写缓存（`pdfjs.getData()` 会拉满全部字节，大文件在慢带宽下拖垮所有预览）。
- **不要**在后台一次性渲染全部页（大 PPT 会占满 CPU/内存）；只渲染当前页 + 下一页。

## 4. 转换缓存与中间文件

转换由 `GotenbergConversionService`（Gotenberg + LibreOffice headless）执行，产物落在 `{StorageRoot}/{OfficeConversion:CacheDirectory}/`（默认 `uploads/converted/`）。

| 文件 | 作用 | 是否必需 |
|------|------|---------|
| `{resourceId}.pdf` | 转换后的整份 PDF（预览与缩略图的数据源） | ✅ 核心产物 |
| `{resourceId}.meta` | 源文件 `LastWriteTimeUtc + Length` 快照。转换前比对：一致则命中缓存跳过转换，源文件变化（换版本）自动失效重转。 | ✅ 避免重复转换 |
| `{resourceId}.light.pptx` | >30MB 大 PPTX 的**媒体预压缩包**（大图/GIF 用 ffmpeg 压小）。LibreOffice 加载大 PPTX 时会把全部媒体读入内存，预压缩显著降低峰值内存与耗时，防止 OOM。 | ✅ 大文件防 OOM |
| `{resourceId}.light.meta` | light 包对应的源文件快照，源文件变化时重建 light。 | ✅ |
| `{resourceId}.repaired.pptx` | 截断/损坏 PPTX（缺 ZIP 中央目录）的**修复包**：重建 ZIP 结构后交给 LibreOffice。 | ⚠️ 仅损坏文件 |
| `{resourceId}.repaired.meta` | 修复包对应的源文件快照。 | ⚠️ 仅损坏文件 |
| `{StorageRoot}/thumbnails/{versionKey}_400.jpg` | 缩略图缓存。 | ✅ |

> `.meta` 与 `.light.pptx` 是**转换服务的内部机制**，不是遗留代码，请保留。
> 转换缓存失效（源文件变化）时，`InvalidateCache` 会一并清理 PDF / meta / 修复包 / light 包。

## 5. 失败与恢复

- **转换失败**：`ResourceMediaProcessor` 记录 Failed 生成物并写 `ErrorMessage`，`ResourceMediaJob` 置 Failed/PartialFailed，`Resource.MediaStatus` 同步。资源任务页可见错误。
- **预览表现**：`preview-pdf-info` 一直 `ready=false` → 前端 loading → 10 分钟后「文档转换超时」。**不会**由前端重新触发转换。
- **重新转换**：在资源任务页点「重新生成」（`ResourceMediaJobManager.RetryAsync`）重新入队媒体任务。
- **历史数据回填**：`ResourceMediaMaintenanceJob`（RecurringJob `resource-media-maintenance`，每 30 分钟）为「有文件但无任何媒体任务」的已审核资源补建任务；同时清理孤儿生成物。
- **中断任务恢复**：`ResourceMediaTaskRecoveryService`（RecurringJob `resource-media-recovery`，每 5 分钟）把超时的 Running 任务标记失败。

## 6. 后端组件清单

| 文件 | 职责 |
|------|------|
| `ResourceMediaJob` (Domain) | 媒体处理任务实体（状态 / 进度 / 错误 / 版本）。 |
| `ResourceMediaJobManager` | 创建并入队媒体任务；同版本 Pending/Running 去重；`RetryAsync` 重试。 |
| `HangfireResourceMediaJobQueue` | Hangfire「media」队列实现。 |
| `ResourceMediaProcessingJob` | 任务执行器：驱动 Processor，回写状态/进度，更新 `Resource.MediaStatus`。 |
| `ResourceMediaProcessor` | 核心：按文件类型生成缩略图 / 预览 PDF，登记 `ResourceArtifact`。 |
| `ResourceArtifact` (Domain) | 生成物登记（Kind=Thumbnail/PreviewPdf，Variant，State，FilePath）。 |
| `GotenbergConversionService` | Office → PDF 转换（缓存、并发闸门、大 PPTX 预压缩、损坏 PPTX 修复）。 |
| `PptxImagePreprocessor` | 大 PPTX 媒体预压缩（light 包）。 |
| `ConversionConcurrencyManager` | 按服务分组（preview/reprocess）控制转换并发，默认串行，防打爆 CPU。 |
| `ResourceMediaMaintenanceJob` | 回填历史资源 + 清理孤儿文件。 |
| `ResourceMediaTaskRecoveryService` | 中断任务恢复。 |
| `ResourceFileController` | 预览/下载/缩略图端点（只读生成物，不触发转换）。 |

## 7. 已移除的遗留流程（勿再引入）

为避免重复维护，以下历史实现已删除：

- **PPTX 服务端逐页提取预览**：`/slides/count`、`/slides/{n}`、`/media/{*path}` 端点及 `pptx-viewer` 组件（坐标还原版式，保真度低）。Office 统一走 PDF。
- **Word 客户端解析**：`word-viewer`（mammoth）及对应 npm 依赖（Word 统一走 PDF）。Excel 仍保留 SheetJS 客户端渲染。
- **PDF 逐页拆分**：`/preview-pdf-page/{n}` 端点与 `GetPagePdfPath`（拆分会让每页复制共享字体/图片，体积暴涨）。
- **前端触发转换**：`IConversionTaskQueue` / `OfficeConversionJob` / `/preview-pdf-info` 兜底入队 / `/preview-pdf` 同步转换兜底。
- **Office 转换预热 RecurringJob**：`OfficeConversionReprocessJob`（与维护任务回填重复）。
- **PDF 整份下载写 Cache Storage**：`pdf-preview-cache` 与 `doc.getData()` 全量缓存。

## 8. 关键配置（`OfficeConversion`）

| 配置 | 默认 | 说明 |
|------|------|------|
| `BaseUrl` | `http://localhost:3000` | Gotenberg 地址（生产为 Docker 内网 `http://gotenberg:3000`）。 |
| `ConversionTimeoutSeconds` | `120` | 单次转换超时。 |
| `MaxPreviewFileSizeBytes` | `100MB` | 超过则不转换，预览降级为「下载查看」。 |
| `ReduceImageResolutionThresholdBytes` | `30MB` | 超过则转换时降采样图片。 |
| `CacheDirectory` | `converted` | 转换缓存目录（相对存储根）。 |
| `EnablePptxPreprocess` | `true` | 大 PPTX 媒体预压缩开关。 |
