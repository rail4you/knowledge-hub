# 登录流程（纯 Angular SPA · 密码授权）

> 适用范围：`angular/` 前端（管理端 + 学生门户）+ `KnowledgeHub.HttpApi.Host` 后端。
> 结论：登录/登出已完全在 Angular 侧完成，不再经过后端 Razor 登录页。

## 1. 总览

| 项目 | 值 |
|------|-----|
| 授权模式 | OAuth2 Resource Owner Password Credentials（`password` grant） |
| OAuth 服务端 | ABP + OpenIddict（`/connect/token`） |
| OAuth 客户端库 | `angular-oauth2-oidc`（经 `@abp/ng.oauth` 封装） |
| 前端配置 | `oAuthConfig.responseType = 'password'` |
| 凭据提交 | Angular 直接 `POST /connect/token`，**不经过后端 Razor 登录页** |
| 登录后落点 | `/post-login`（守卫按角色分发） |

关键点：`AuthPasswordFlowStrategy.login()` 会读取 `SessionStateService` 的当前租户，并在 token 请求里带上 `__tenant` header；`AuthCodeFlowStrategy` 则会忽略凭据、直接跳转后端。因此**任何环境都必须使用 `password`**，否则登录会退化为 Razor 页面授权码流程。

| 文件 | 职责 |

## 3. 运行时配置

### 3.1 开发环境
- 真源：`angular/src/environments/environment.ts`（`responseType: 'password'`）。
- `issuer`/`apis.default.url` 指向 `http://localhost:4200`，由 `angular/proxy.conf.js` 代理 `/api`、`/connect`、`/.well-known` 到 `https://localhost:44305`。
- 开发环境**不读取** `angular/dynamic-env.json`（`environment.ts` 未配置 `remoteEnv`）。

### 3.2 生产环境
- 构建时 `environment.ts` 被替换为 `environment.prod.ts`，其中配置了：
  ```ts
  remoteEnv: { url: '/getEnvConfig', mergeStrategy: 'deepmerge' }
  ```
- Nginx 把 `/getEnvConfig` 映射到容器内 `/usr/share/nginx/html/dynamic-env.json`（由 `etc/docker/deploy.sh gen-env` 从 `dynamic-env.template.json` 生成，docker-compose 挂载）。
- `deepmerge` 会用远端值**覆盖**本地标量，因此 `etc/docker/dynamic-env.json` 与 `etc/docker/dynamic-env.template.json` 的 `responseType` **也必须是 `password`**，否则生产环境会退回授权码流程并重新依赖 Razor 登录页。

### 3.3 后端客户端权限
`src/KnowledgeHub.Domain/OpenIddict/OpenIddictDataSeedContributor.cs` 中 `KnowledgeHub_App` 客户端：
- `ClientTypes.Public`（无 secret）
- 允许 `AuthorizationCode / Password / ClientCredentials / RefreshToken` 等 grant

> 注意：若数据库中的客户端是在「加入 Password grant」之前种子的，需要重新执行种子（DbMigrator）才会生效。

## 4. 登录时序

### 4.1 租户用户登录（`/account/login`）
1. `LoginComponent.ngOnInit()` → `loadTenants()` 拉取 `/api/public/tenants`，过滤掉 `{id:null,"全局"}` 占位项；无有效 cookie 时自动选中第一个租户。
2. `selectTenant()` 同时写：
   - cookie `__tenant=<tenantId>`
   - `SessionStateService.setTenant({id,name})`（密码授权 token 请求据此发 `__tenant` header）
3. 提交 → `authService.login({username,password,rememberMe,redirectUrl:'/post-login'})`
   → `fetchTokenUsingPasswordFlow()` → `POST /connect/token`（带 `__tenant` header）。
4. 后端 `KnowledgeHubSignInManager.PreSignInCheck()` 校验：
   - 用户 `TenantId` 必须等于当前解析租户；
   - 用户名 `admin` 禁止在租户上下文登录。
5. 成功后 `pipeToLogin` 先 `refreshAppState()`（加载 `currentUser.roles`），再 `router.navigate(['/post-login'])`。
6. `postLoginGuard` 校验租户一致后按角色分发（见 §5）。

### 4.2 宿主管理员登录（`/admin-login`，或 `/account/login?host=true`）
1. `isHostLogin = true`：清除 `__tenant` cookie + `SessionStateService.setTenant(null)`，不拉取租户列表。
2. 提交 → token 请求**不带** `__tenant` header → 后端签发宿主 token（无 `tenantid` 声明）。
3. 登录成功直达 `/admin/workbench`（默认 redirectUrl，不经过 `/post-login`）。

## 5. 登录后角色分发（`post-loginGuard`）

`resolvePostLoginUrl()`：
- 未认证 → `/account/login`
- 持有任一 `ADMIN_ROLES`（`Teacher / SchoolAdmin / LeagueAdmin / EnterpriseUser / admin`）→ `/admin/workbench`
- 其余（学生 / 无角色）→ `/student`

租户一致性兜底：比较 cookie `__tenant`（用户所选机构）与 access token 的 `tenantid` 声明。
- 无 `__tenant`（宿主通道）→ 跳过校验；
- 不一致 → 清空 token + cookie、`refreshAppState()` 回匿名、跳回 `/account/login?error=tenant-mismatch`，登录页订阅 `queryParamMap` 展示行内错误。

## 6. 登出

`CustomAuthService.logout()`：
1. 先清 `__host_login`（历史残留）与 `__tenant` cookie（登出即忘记租户）；
2. `super.logout()` → `AuthPasswordFlowStrategy.logout()`：
   `revokeTokenAndLogout(true)`（`noRedirectToLogoutUrl=true`，**不跳转** OIDC end-session）→ `refreshAppState()` → `navigateByUrl('/')`。

即密码授权登出是纯客户端行为，不会跳到后端页面。

## 7. 会话保持 / 刷新 / 记住我

- token 由 `angular-oauth2-oidc` 存储，ABP 的 `MemoryTokenStorageService` 把 `access_token`/`expires_at` 等放在 SharedWorker 内存（跨标签共享），`refresh_token` 落盘 localStorage。
- `scope` 含 `offline_access` → 返回 `refresh_token`；`AuthPasswordFlowStrategy.listenToTokenExpiration()` 在 access token 过期时自动刷新。
- 刷新失败 → `clearOAuthStorage()` 清空并回登录页。

### 7.1 「记住我」的实际语义（本项目已修复）

ABP 默认行为下，`refresh_token` 始终落盘 localStorage，启动时会无条件用它刷新，导致**未勾选「记住我」也会长期在线**，勾选框形同虚设；且 `pipeToLogin` 用 `params.rememberMe || get()`，一旦勾选过就无法再关闭。

`CustomAuthService` 做了两处修复：

| 位置 | 修复 |
|------|------|
| `login()` | 强制 `rememberMeService.set(!!params.rememberMe)`，让取消勾选真正生效；未勾选时写入会话标记 `kh_auth_session` |
| `init()` | 未勾选时用 `sessionStorage` 标记区分「刷新页面」与「浏览器重启」 |

未勾选时的判定逻辑：`sessionStorage` 在页面刷新时保留、浏览器重启时清空。
- 有标记（刷新页面）→ 保留 `refresh_token`，会话内 1 小时续期照常；
- 无标记（浏览器重启）→ 清除 `refresh_token`，下次需重新登录。

实测（Playwright）：

| 场景 | 勾选「记住我」 | 未勾选 |
|------|--------------|--------|
| 登录成功 | 进入工作台 | 进入工作台 |
| 刷新页面 | 保持登录 | 保持登录 |
| 浏览器重启 | 仍登录（refresh_token 续期） | 需重新登录 |


## 8. 健壮性兜底

1. **机构未就绪禁止提交**：`onSubmit()` 在租户通道下若 `currentTenantId()` 为空（机构列表加载失败或未选中），直接拦截并提示，避免以残留租户上下文登录。
2. **登录成功跳转兜底**：登录成功后启动 10s 计时器；若届时组件仍未卸载（说明 `/post-login` 或目标页 chunk 加载失败），自动解除「正在进入系统…」并提示重试。组件正常卸载时 `ngOnDestroy` 清除计时器。
3. **租户不一致回退**：`postLoginGuard` 检测到 token 租户与所选机构不符时，清空 token/cookie、回匿名并跳回 `/account/login?error=tenant-mismatch`，登录页订阅 `queryParamMap` 展示行内错误。

## 9. 遗留与注意事项

1. **`__host_login` 已是历史产物**：Angular 不再写入，仅在登出/租户不匹配时防御性清除；Razor 登录页仍会读取它。
2. **后端 Razor 登录页仍保留**（按当前决定暂不清理）：`src/KnowledgeHub.HttpApi.Host/Pages/Account/Login.cshtml` + `KnowledgeHubLoginModel.cs` 仍可访问（200），SPA 已不再使用；目前唯一消费者是 Swagger 的授权码「Authorize」流程。
3. **`login.component.ts` 的 `clearSession()`** 仍清理 `idsrv` / `.AspNetCore.Identity.Application` 等 IdentityServer cookie，这些在纯密码授权下不会由浏览器写入，属冗余但无害。
4. 语言菜单已隐藏但**功能按注释保留**（`loadLanguages` / `onChangeLang` / `toggleLangDropdown` 等），后续开放多语言时可直接复用。
5. 登录输入框（用户名/密码）已用 `:-webkit-autofill` 覆盖浏览器自动填充的灰/蓝底色，填充后与未填充保持一致的白底。
