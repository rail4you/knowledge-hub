# 多校资源库架构设计（学校 / 专业 / 共建资源库 / 社会学校）

> 对应原始需求三条：
> 1. 租户按学校层级，租户下多专业；资源库按专业维度显示；资源库多校共建（主建学校 + 合作学校）；库内课程 / 资源 / 习题有专业维度限制。
> 2. 租户对应的学校是独立实体（学校简介、学校徽标等配置项），首页显示学校徽标和名称，点击跳转到学校简介。
> 3. 平台唯一「社会学校」租户，学生可自由注册；课程和资源可一键共享到社会学校。

---

## 一、总体模型

```
ABP Tenant（= 一所学校）
 ├── School            学校档案（1:1，全局实体）：徽标 / 横幅 / 简介 / 联系方式 / 是否公开展示
 ├── Major[]           专业（租户级）：库与内容的主专业维度
 ├── ResourceLibrary[] 资源库（租户级，主建学校拥有）
 │    └── ResourceLibraryMember[]  共建成员：Owner=主建学校，Partner=合作学校
 ├── Resource / Course / Exercise    内容，通过 LibraryId 归属库，通过 MajorId 落专业维度
 └── CourseShare / ResourceShare     跨校共享记录（目标可含社会学校）
```

### 关键设计取舍

| 取舍 | 决策 | 理由 |
|---|---|---|
| 学校档案是否租户级实体 | **否**，`School` 是全局实体，只以 `TenantId` 唯一索引关联 | 学校描述的正是租户本身；若实现 `IMultiTenant`，门户公开接口无法跨租户读取全部学校 |
| 资源库归属 | **主建学校的租户级实体** + 成员表 | 库内资源仍属主建学校，ABP 租户过滤器不被打破；合作学校通过成员关系获得可见性 |
| 社会学校 | **平台层面唯一**租户（设置项 `KnowledgeHub.PublicSchool.TenantId`） | 所有公开注册统一进入该租户；一键共享目标唯一确定，无需在 UI 上选目标 |
| 共建库专业限制 | 库绑定 `PrimaryMajorId`；内容挂库时校验主专业一致 | 需求「库内课程 / 资源 / 习题有专业维度限制」落到后端强制校验，而非仅前端筛选 |

## 二、数据模型

### 2.1 新增实体

| 实体 | 表 | 关键字段 |
|---|---|---|
| `School` | `AppSchools` | `TenantId`（唯一）、`Name`、`LogoUrl`、`BannerUrl`、`Introduction`、`Website`、`Address`、`ContactPhone`、`ContactEmail`、`IsPublic`、`SortOrder` |
| `ResourceLibrary` | `AppResourceLibraries` | `TenantId`(=主建学校)、`OwnerTenantId`、`PrimaryMajorId`、`Name`、`Description`、`CoverUrl`、`Status`、`IsPublic`、`SortOrder` |
| `ResourceLibraryMember` | `AppResourceLibraryMembers` | `LibraryId`、`MemberTenantId`、`MemberTenantName`、`Role`(Owner/Partner)、`JoinedTime`、`TenantId`(=库归属) |
| `CourseShare` | `AppCourseShares` | `CourseId`、`SourceTenantId`、`TargetTenantId`、`SharedByUserId`、`SharedAt`、`Note`、`TenantId`(=源租户) |

### 2.2 既有实体扩展

| 实体 | 新增字段 | 说明 |
|---|---|---|
| `Resource` | `LibraryId` | 归属资源库（FK → `AppResourceLibraries`，`SetNull`） |
| `Course` | `LibraryId` | 同上 |
| `Exercise` | `LibraryId`、`MajorId` | 习题创建时从所属课程继承 |

### 2.3 枚举

- `ResourceLibraryStatus`：Draft=0（仅主建可见）/ Active=1（共建共享）/ Archived=2
- `ResourceLibraryMemberRole`：Owner=0（主建）/ Partner=1（合作）

## 三、后端接口

### 3.1 学校档案 `ISchoolAppService` → `/api/app/school/*`

| 方法 | 路由 | 权限 |
|---|---|---|
| `GetCurrentAsync` | `GET /current` | `KnowledgeHub.Schools.Default` |
| `UpdateCurrentAsync` | `PUT /current` | `KnowledgeHub.Schools.Edit` |
| `GetProfileAsync(tenantId)` | `GET /profile/{tenantId}` | 匿名（学校简介页） |
| `GetPublicListAsync` | `GET /public-list` | 匿名（首页 / 注册页） |
| `GetPublicSchoolAsync` | `GET /public-school` | 匿名 |
| `SetPublicSchoolAsync(tenantId)` | `POST /set-public-school/{tenantId}` | `KnowledgeHub.Schools.ManagePublicSchool`（Host-only） |

### 3.2 资源库 `IResourceLibraryAppService` → `/api/app/resource-library/*`

`GET /`（列表，可见=本租户主建 + 本租户参与共建）、`GET /{id}`、`POST /`（建库，当前租户自动成为主建学校）、
`PUT /{id}`、`DELETE /{id}`、`POST /{id}/member`（加合作学校）、`DELETE /{id}/member/{tenantId}`（移除）。

### 3.3 课程共享 `ICourseShareAppService` → `/api/app/course-share/*`

`POST /share`、`POST /share-to-public-school/{courseId}`（一键共享到社会学校）、`DELETE /unshare`、
`GET /shares/{courseId}`、`GET /shared-to-me`、`GET /shared-by-me`。

### 3.4 资源共享（既有 `IResourceShareAppService` 扩展）

新增 `POST /api/app/resource-share/share-to-public-school/{resourceId}`。

### 3.5 公开注册 `IPublicRegistrationAppService` → `/api/app/public-registration/*`

- `POST /register`（匿名）：用户名 / 邮箱 / 密码 / 姓名 / 手机号 → 在社会学校租户下建号并授予 `Student` 角色
- `GET /social-school`（匿名）：社会学校信息（注册页展示；未配置时 `configured=false`）

> **实现要点**：`IdentityUser.TenantId` 是 `protected set`，必须通过构造函数传入；
> 注册时先 `CurrentTenant.Change(socialSchoolId)` 再 `new IdentityUser(id, user, email, CurrentTenant.Id)`，
> 否则会建成宿主用户。`PhoneNumber` 同样没有公开 setter，需走 `SetPhoneNumber()`。

### 3.6 门户集成

`PortalAppService.GetPublicTenantListAsync` 补 `LogoUrl`（取自 `School`）与 `TenantName`（优先 `School.Name`）。

| 页面 | 路由 | 说明 |
|---|---|---|
| 学校简介页 | `/school/:id` | 校徽 + 校名 + 联系方式 + 统计 + 学校简介 + 专业清单 + 共建资源库（含主建/合作成员） |

## 六、存量数据自愈

- **学校档案回填**：`SchoolProvisioningEnsureHostedService` 在 API 启动时遍历所有租户，
  为缺失档案的租户补建一份（名称取租户名）。新建租户则由 `SchoolProvisioningHandler`
  订阅 `EntityCreatedEventData<Tenant>` 即时建卡。
- **存量租户的用户看不到校徽**属于预期——校徽需由学校管理员在 `/admin/school` 自行上传。

## 八、已知边界

1. **共享给社会学校有前置条件**：资源必须已通过院校审核（`SchoolApproved` / `LeagueApproved`），
   与既有「共享给其他租户」规则一致。
2. **社会学校不可自共享**：当前租户就是社会学校时，一键共享直接拒绝（避免自我共享记录）。
3. **共建库的内容读取路径**目前只打通到「库与成员」层面；库内资源 / 课程在合作学校的
   列表页读取仍走各自租户的常规查询，需要在前端资源库页面按 `LibraryId` 追加联合查询。
4. **校徽图片为 URL 字段**（非文件上传）。若需要后台上传，可复用既有 OSS 上传通道写入
   `School.LogoUrl`。
