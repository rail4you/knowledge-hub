## 二、已修复详情

### #1 工作台章节数口径不一致
- **文件**：`src/KnowledgeHub.Application/Workbench/WorkbenchAppService.cs`
- **根因**：`chapterQuery.LongCountAsync()` 未过滤 `ParentId`，把子章节也计入；课程列表/详情用 `ParentId == null`（一级章节）。
- **修复**：与课程列表统一为一级章节口径。
- **验证**：
  ```
  qidi 租户 全部层级章节 = 166（修复前口径）
  qidi 租户 一级章节     = 19 （修复后口径）
  课程列表各课 chapterCount 合计 = 7+0+7+1+4 = 19  ✅ 一致
  ```

### #4 门户 footer 过高
- **文件**：`angular/src/app/home/portal-home.component.scss`
- **修复**：`padding: 34/35px → 22/18px`，内容行 `margin-bottom: 25px → 14px`，版权行 `padding-top: 19px → 12px`。

### #5 工作台横幅文字对比不足
- **文件**：`angular/src/styles/_kh-ui.scss`
- **修复**：标题改为纯白 + 轻微 `text-shadow`；正文由 `--kh-on-deep(#d5e1dc)` 提升到 `rgba(255,255,255,.9)` + 阴影。

### #6 搜索无结果体验
- **文件**：`angular/src/app/student/search/student-search.component.{html,ts,scss}`
- **说明**：实测 `POST /api/app/search/search` 对现有数据（搜「测试」）**可正常返回结果**，索引内共 41 篇文档（4 个资源）。qidi 租户确实没有含「中医」的索引内容，故空结果属预期。
- **修复**：空结果时补充「去资源库看看 / 清空重填」操作与「仅搜索已建索引资源」说明。

### #7 热门词为空
- **文件**：`angular/src/app/ai/chat/chat.component.{html,scss}`
- **说明**：`GetHotWordsAsync` 链路（Meili → DB 回退 → 分词 → 可召回校验）健壮；返回空是因为该资源无 `PageContent`。
- **修复**：空态补充「该资源尚未生成页面索引，完成索引后将自动提取关键词」。

### #8 AI 习题分值不一致 + 英文
- **文件**：`src/KnowledgeHub.Application/Exams/ExerciseAiGenerator.cs`
- **根因**：prompt 中 `"score": 1（建议 1-10）` 只给示例值，模型自行给分（同难度判断题出现 3/3/4）。
- **修复**：
  1. 按题型定基准分值（单选 2 / 多选 3 / 判断 2 / 填空 3 / 简答 5），难度做 +1 或 +2；
  2. 把**算好的固定分值**写入 prompt，并要求所有题目统一；
  3. **后端兜底强制** `Score = fixedScore`，忽略模型返回值；
  4. prompt 增加「全部内容必须使用简体中文，不得出现英文单词或缩写」。

### #10 就业统计环形图不居中
- **文件**：`angular/src/app/admin/employment/employment-statistics.component.{scss,ts}`
- **根因**：`.chart-box { display:flex; justify-content:center }` 使 ECharts 内部 div 收缩，canvas 只画在左侧；且无 resize 监听。
- **修复**：移除容器 flex 居中；新增 `ResizeObserver` → `chart.resize()`。

### #11 直播归入实训而非就业
- **文件**：`angular/src/app/route.provider.ts`
- **修复**：`/admin/recruitment-live` 的 `parentName` 由 `::Menu:TrainingManagement`（就业管理）改为 `::Menu:PracticumGroup`（实训）。

### #13 用户单角色约束
- **文件**：`src/KnowledgeHub.Application/Identity/TenantUserAppService.cs`
- **根因**：`EnsureNoLeagueAdminForTenantUser` 只拦「联盟管理员」，未校验角色数量。
- **修复**：新增单角色校验——去重后超过 1 个角色直接 `UserFriendlyException`，创建/编辑统一生效。
- **待补**：历史数据中已存在的双角色用户需一次性清理（见「后续建议」）。

### #14 登录即弹 AI 任务通知
- **文件**：`angular/src/app/ai/services/ai-task-notification.service.ts`
- **根因**：`forkJoin` 中 `getMyCompleted` 的 `catchError` 吞掉了失败，但仍执行 `seeded = true`，把「空列表」当基线；下次轮询把所有历史任务判为「新完成」并集中弹窗。
- **修复**：
  1. 用 `itemsOk` 标记请求是否真正成功，失败时不建立基线、不弹通知；
  2. 增量异常大（>5 条）时按基线处理，避免刷屏。

### #16 课程详情自动滚到底部
- **文件**：`angular/src/app/app.config.ts`
- **根因**：未配置路由滚动行为，章节树默认展开导致 DOM 高度骤增，浏览器保留旧滚动锚点。
- **修复**：`provideRouter(APP_ROUTES, withInMemoryScrolling({ scrollPositionRestoration: 'top', anchorScrolling: 'disabled' }))`。

### #18 工作台按钮间距
- **文件**：`angular/src/app/student/dashboard/student-dashboard.component.scss`
- **修复**：`.welcome__actions` 的 `gap` 由 12px 放宽到 16px。

### #19 我的学习图表 resize
- **文件**：`angular/src/app/student/my-learning/student-my-learning.component.ts`
- **修复**：新增 `ResizeObserver`（父级 grid 异步布局变宽时重绘），保留原 window resize 兜底。

### #21 微专业卡片标签框
- **说明**：该页已在前期 v4 改版中重构为原型色块封面（`.cover` 色块 + `.coursebody`），旧的带框标签已不存在，无需额外改动。

### #22 提交任务弹窗点 × 无反应（P0）
- **文件**：`angular/src/app/student/agent-tasks/student-agent-task-detail.component.{html,ts}`
- **根因**：`ng-zorro-antd@21` 的 `NzModalRef.trigger()` 实现：
  ```js
  const { trigger } = actionMap[action];   // trigger = config.nzOnCancel
  if (trigger instanceof EventEmitter) { trigger.emit(...) }
  else if (typeof trigger === 'function') { ... }
  // 两者都不满足时直接返回：既不关闭弹窗，也不 emit nzVisibleChange
  ```
  页面只绑了 `[nzVisible]` + `(nzVisibleChange)`，**没有 `nzOnCancel`**，因此点 × 完全无响应（而 footer 里的「取消」按钮是自己写的 `signal.set(false)`，所以正常）。
- **修复**：为该页两个弹窗补 `(nzOnCancel)`；并把内联 `signal.set($event)` 改为具名方法（便于后续维护与日志）。
- **验证**：
  ```
  打开前  : modals = 0
  打开后  : modals = 1 (可见)
  点 × 后 : modals = 0  ✅ 已关闭（修复前仍为 1）
  ```
- **附带发现**：全项目扫描后，仅此 2 处 `<nz-modal>` 缺少 `nzOnCancel`，其余弹窗写法正确，无同类隐患。

## 六、风险与回归提示

1. **#1 章节数口径变更**：工作台「章节数」数值会**明显下降**（166→19），属预期修正；如有报表依赖旧口径需同步说明。
2. **#8 分值兜底**：已生成的旧习题分值不受影响，仅新生成任务生效；如需统一历史数据需额外脚本。
3. **#13 单角色校验**：若存在「一人多角色」的合法业务场景（如班主任兼授课教师），需放宽为白名单组合。
4. **#16 全局滚动行为**：`scrollPositionRestoration: 'top'` 为全局配置，会影响所有路由的滚动重置；如个别页面（如搜索结果返回）需要保留位置，可对该路由单独处理。
5. **#22 弹窗修复**：仅补 `nzOnCancel`，不改变既有交互（取消按钮、提交逻辑）。全项目仅此 2 处缺失，无同类隐患。
